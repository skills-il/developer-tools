# שיטות עבודה ב-open-slide למפתחים ישראלים

> מבוסס על [open-slide/open-slide](https://github.com/open-slide/open-slide) (MIT, לשעבר <bdi>1weiho/open-slide</bdi>). התאמות עברית ו-RTL על ידי [skills-il](https://agentskills.co.il).

## בעיה

הפריימוורק open-slide מגיע עם מערכת כתיבה ייחודית: קאנבס קבוע 1920×1080 מבוסס React, אובייקט DesignSystem עם טיפוסים, תיקיית themes, אינספקטור שמטמיע סמני `@slide-comment` בקוד המקור, וחמש סקילים מובנות (`slide-authoring`, `create-slide`, `create-theme`, `apply-comments`, `current-slide`). אף אחת מהן לא נוגעת בעברית או ב-RTL. בלי הסקיל הזה, מצגת שאיג'נט כותב יוצאת מיושרת לשמאל, עם פונטים מערכתיים בלבד, `paddingLeft` שדוחף את הטקסט לכיוון הלא נכון, ובלי שום הנחיה לערבוב עברית ולועזית. מפתחים ישראלים מבזבזים שעות על התאמת RTL בדיעבד, על טעינת פונטים עבריים מ-Google Fonts, ועל גילוי שגדלי טיפוגרפיה שכוונו לטקסט באנגלית לא עוברים לעברית באופן אמין.

## הוראות

### מתי להשתמש

השתמשו בסקיל הזה כל פעם שאתם כותבים או עורכים קוד ב-`slides/<id>/` בפרויקט open-slide, יוצרים ערכת נושא ב-`themes/`, או מעבדים הערות מהאינספקטור, ובמיוחד אם התוכן בעברית או דו-לשוני.

### יצירת פרויקט חדש

בתיקייה ריקה או בסביבת עבודה ללא פרויקט open-slide קיים, צרו אחד עם:

```bash
npx @open-slide/cli init my-slide
cd my-slide
npm run dev
```

החליפו את `my-slide` בשם פרויקט מתאים. הסקאפולדר מתקין את התלויות, מריץ <bdi>git init</bdi> עם קומיט ראשון, ומדפיס `npm run dev` כשלב הבא. הפקודה <bdi>init</bdi> מקבלת `--use-pnpm` / `--use-yarn` / `--use-bun` / `--use-npm` לבחירת מנהל החבילות, ו-`--no-install` / `--no-git` כדי לדלג על השלבים האלה.

**גרסת <bdi>Node</bdi>.** <bdi>core 2.x</bdi> מצהיר `"node": "^20.19.0 || >=22.12.0"`, אבל ה-CLI תלוי ב-`commander@15` שמצהיר `">=22.12.0"`, וב-`chalk@6` (`">=22"`). על <bdi>Node 20.19</bdi> הסקאפולד עדיין מסתיים, אבל npm מדפיס `EBADENGINE Unsupported engine` לשתיהן. השתמשו ב-<bdi>Node 22.12</bdi> ומעלה.

**מלכודת מונחים.** ב-open-slide, "שקף" (<bdi>slide</bdi>) הוא מצגת שלמה (תיקייה אחת), וה"עמודים" (<bdi>pages</bdi>) הם מה שמשתמש קורא לו שקפים. "מצגת של 10 שקפים" פירושה עשרה עמודים בתוך <bdi>slides/&lt;id&gt;/index.tsx</bdi> אחד, לא עשר תיקיות.

מה שהסקאפולד נותן לכם:

| נתיב | מה זה |
| --- | --- |
| `slides/<id>/index.tsx` | תיקייה אחת לכל מצגת. ראו את כלל המזהה למטה. |
| `themes/` | ערכות נושא (<bdi>&lt;id&gt;.md</bdi> ועוד <bdi>&lt;id&gt;.demo.tsx</bdi>) |
| `assets/` | נכסים גלובליים שמשותפים לכמה מצגות, מיובאים דרך `@assets/...` |
| `open-slide.config.ts` | ייצוא מטיפוס `OpenSlideConfig`, ריק כברירת מחדל. ההגדרות: `base`, `slidesDir`, `themesDir`, `assetsDir`, `port`, `allowedHosts`, `build`, `agent`, ו-`locale` שסומן כמיושן. |
| `.agents/skills/` ו-`.claude/skills/` | חמשת הסקילים המקוריים, מועתקים פנימה בזמן ה-init |
| `AGENTS.md` / `CLAUDE.md` | כללי ניתוב קצרים שאומרים לסוכן קוד באיזה סקיל מצורף להשתמש |
| `npm run sync:skills` | מעתיק מחדש את הסקילים המצורפים מתוך `@open-slide/core` אחרי שדרוג |

הריצו `npm run sync:skills` אחרי כל שדרוג של `@open-slide/core`, אחרת הסוכן ממשיך לקרוא את עותקי הסקילים מהגרסה שאיתה יצרתם את הפרויקט.

### על איזו גרסה אתם

כוונו ל-**<bdi>@open-slide/core</bdi> בגרסה <bdi>2.x</bdi>**. גרסה 2 יצאה לגרסה יציבה ב-<bdi>2026-09-26</bdi>, התג <bdi>latest</bdi> ב-npm מצביע עליה, ו-<bdi>npx @open-slide/cli init</bdi> יוצר פרויקט עליה. כל מה שכתוב בסקיל הזה נבדק מול **<bdi>2.3.1</bdi>**, על ידי יצירת פרויקט והרצת ה-build והייצואים שלו.

**שדרוג פרויקט <bdi>v1</bdi>.** קוד השקפים לא דורש שינוי; מדריך המעבר הרשמי מצמצם את המעבר ל-<bdi>package.json</bdi>, לגרסת Node ולהגדרות הפריסה. עדכנו את <bdi>@open-slide/core</bdi> ל-<bdi>^2.0.0</bdi> ואת <bdi>react</bdi> / <bdi>react-dom</bdi> ל-<bdi>^19.2.8</bdi>, התקינו מחדש, ואז הריצו `npm run sync:skills`.

**הדבר היחיד שנשבר בשדרוג.** פרויקט שנוצר ב-v1 מכיל <bdi>vite</bdi> ב-<bdi>devDependencies</bdi>, ואילו <bdi>core 2.x</bdi> מביא <bdi>Vite 8</bdi> משלו. אם תשאירו את השורה הישנה, <bdi>dev</bdi>, <bdi>build</bdi> ו-<bdi>preview</bdi> כולם מסרבים לעלות:

```
✖ Remove vite from your package.json
  devDependencies in package.json still lists vite, a leftover from v1.
  It shadows the vite@8.3.5 bundled with open-slide: @tailwindcss/vite
  is loading vite@5.4.21 from node_modules/vite instead.
    $ npm uninstall vite
```

הריצו את פקודת ההסרה שמודפסת (היא מותאמת למנהל החבילות שלכם). פרויקטים חדשים ב-v2 לא כוללים <bdi>vite</bdi>, ומגיעים עם <bdi>vercel.json</bdi> / <bdi>netlify.toml</bdi> כדי שהאחסון עדיין יידע איך לבנות. מדריך המעבר: <https://open-slide.dev/docs/migrate-to-v2>.

### מזהי תיקיות השקפים חייבים להיות באנגלית (שמות בעברית נזרקים בשקט)

**אל תקראו לתיקיית שקף בעברית.** מנגנון הגילוי מסנן כל תיקייה תחת `slides/` דרך `SLIDE_ID_RE = /^[a-z0-9_-]+$/i` ומדלג על השאר, כך שתיקייה כמו `slides/פתיחה/` לא מגיעה לסרגל הצד, לדפדפן, או ל-build. נבדק מחדש על <bdi>@open-slide/core@2.3.1</bdi>, על ידי יצירת פרויקט והרצת <bdi>npm run build</bdi>:

```
[plugin open-slide] Ignoring slide folder "פתיחה": slide ids must match
/^[a-z0-9_-]+$/i (lowercase/uppercase letters, digits, "-", "_"). Rename the folder under
"slides/" to a kebab-case id so it appears in the browser and can be moved into folders.
```

זו אזהרה בלבד, ולכן `npm run build` מסתיים בהצלחה. השתמשו במזהה באנגלית ב-kebab-case (`peticha`, `cover`, `q2-roadmap`), ושימו את העברית ב-`meta.title` ובתוכן העמוד, איפה שהיא שייכת.

**אל תחילו את הכלל הזה יותר מדי רחב.** הוא ספציפי למזהי תיקיות של שקפים. נבדק ואינו מושפע:

| משטח | עברית מותרת? | למה |
| --- | --- | --- |
| שם התיקייה `slides/<id>/` | לא | מסונן על ידי `SLIDE_ID_RE` בשלב הגילוי |
| `meta.title` | כן | טקסט חופשי, אף פעם לא משמש כמזהה |
| שם הקובץ `themes/<id>.md` | כן | מזהה ערכת הנושא הוא `path.basename(file, '.md')` בלי שום סינון ASCII, והנתיבים נבנים עם `encodeURIComponent(id)` |
| ערכים ב-frontmatter של ערכת נושא (`name:`, `description:`) | כן | רק המפתח ב-frontmatter נבדק מול `/^([A-Za-z0-9_-]+)\s*:/`; הערך הוא טקסט חופשי |
| תוכן השקף עצמו | כן | זה סתם טקסט ב-JSX |

### עברית ו-RTL

לכל מצגת בעברית או דו-לשונית, טענו קודם את [./rules/hebrew-rtl.md](./rules/hebrew-rtl.md). הוא מכסה:

- פונטים עבריים מ-Google Fonts (Heebo, Rubik, Assistant, Noto Sans Hebrew) שנטענים בהזרקה ל-head
- הגדרת `dir="rtl"` הנכונה ברמת רכיב הדף, ולא על `<html>` (אחרת ה-chrome של שרת הפיתוח נשבר)
- מאפייני CSS לוגיים (`paddingInlineStart`, `marginInlineStart`, `insetInlineStart`) במקום `paddingLeft`/`marginLeft`/`left`
- שימוש ב-`flexDirection: 'row-reverse'` מול הגדרת `dir` על הקונטיינר הפלקס
- בידוד דו-כיווני עם <bdi>&lt;span dir="ltr"&gt;</bdi> או `<bdi>` לערבוב עברית עם לועזית (שמות מותגים, קוד, URL)
- כוונון סקאלת טיפוגרפיה לעברית (הגדלים של פריסה באנגלית אינם מדד אמין; בדקו בתצוגה מקדימה והתאימו)
- בחירת `DesignSystem.fonts` עבריים ודפוסי ערכת נושא שמתאימים ל-RTL
- מלכודות טיפוגרפיות בעברית: רנדור של ניקוד, מרווחי אותיות סופיות, מקף רגיל לעומת מקף יהודי (maqaf)

### כתיבת שקפים (מבנה הקובץ, קאנבס, סקאלת טיפוגרפיה, ערכות נושא, טוקני עיצוב)

לתיעוד הטכני המלא של מה שנכנס ל-`slides/[id]/index.tsx`, טענו את [./rules/slide-authoring.md](./rules/slide-authoring.md). הקובץ משקף את הסקיל המקורי `slide-authoring` (מבנה הקובץ, חישובי הקאנבס, סקאלת הטיפוגרפיה, ערכות נושא, טוקני `DesignSystem`, תבנית הבסיס, נכסים, תצוגה מקדימה של עמוד) עם הערות עברית/RTL בתוך הטקסט.

מאז, הפרויקט המקורי פיצל את סקיל ה-`slide-authoring` שלו לקבצי reference נפרדים לכל פרימיטיב. שלושה מהם מכסים פרימיטיבים שהסקיל הזה לא משכפל, קראו אותם במקור במקום לממש ביד:

| קובץ ה-reference במקור | הפרימיטיב | למה זה משנה במצגת בעברית |
| --- | --- | --- |
| [`references/steps.md`](https://raw.githubusercontent.com/open-slide/open-slide/f4d840ed1282cb4e2db1280f4a6454113a495383/packages/core/skills/slide-authoring/references/steps.md) | חשיפה מדורגת עם `<Steps>` / `<Step>` | חשיפה מדורגת מאפשרת לשמור כל פסקה עברית קצרה במקום להעמיס עמוד אחד צפוף |
| [`references/page-numbers.md`](https://raw.githubusercontent.com/open-slide/open-slide/f4d840ed1282cb4e2db1280f4a6454113a495383/packages/core/skills/slide-authoring/references/page-numbers.md) | ה-hook בשם `useSlidePageNumber()` | קראו `{ current, total }` מה-hook במקום לקודד מונה בפוטר; עטפו את כל הריצה <bdi>current / total</bdi> ב-<bdi>&lt;span dir="ltr"&gt;</bdi> אחד בתוך פוטר RTL (עטיפה של כל מספר בנפרד עדיין הופכת אותו) |

### כתיבת מצגת חדשה

כשהמשתמש מבקש "תכין שקפים על X" / "תיצור מצגת" / "תכין דק", טענו את [./rules/create-slide.md](./rules/create-slide.md) לזרימת העבודה: בחירת ערכת נושא, ארבע שאלות מנחות (כיוון אסתטי, מספר עמודים, צפיפות טקסט, תנועה), בחירת מזהה לשקף, תכנון מבני, החלטה על הכיוון החזותי, כתיבה, סקירה עצמית, ומסירה למשתמש.

### יצירת ערכת נושא

כשהמשתמש מבקש "תיצור ערכת נושא" / "תכין תמה בשם X" / "תוציא ערכת נושא מהשקף הזה", טענו את [./rules/create-theme.md](./rules/create-theme.md). ערכת נושא היא **צמד קבצים**: `themes/<id>.md` (פלטה / טיפוגרפיה / לאיאוט / רכיבים קבועים / תנועה / אסתטיקה) יחד עם מודול דמו תואם, <bdi>themes/&lt;id&gt;.demo.tsx</bdi> (גם <bdi>.jsx</bdi>, <bdi>.ts</bdi> ו-<bdi>.js</bdi> מתקבלים), מיני-שקף רץ של 2 עד 3 עמודים שפאנל ה-<bdi>Themes</bdi> מציג כתצוגה המקדימה החיה. אם תכתבו רק את קובץ ה-markdown, לערכת הנושא תהיה כרטיסיית תצוגה מקדימה ריקה.

### החלת הערות מהאינספקטור

כשהמשתמש השאיר הערות במצב ההערות של שרת הפיתוח ומבקש "תחיל את ההערות", טענו את [./rules/apply-comments.md](./rules/apply-comments.md): פורמט הסמן, ה-regex לזיהוי, ה-payload המפוענח (כולל <bdi>rect</bdi> של אזור שנגרר), והסדר הנכון להחלה (משורה אחרונה לראשונה).

### פיענוח הפניות דייקטיות ("העמוד הזה", "השקף שאני נמצא עליו")

כשהמשתמש מתייחס לשקף הנוכחי בלי לקרוא לו בשם, טענו את [./rules/current-slide.md](./rules/current-slide.md) **קודם**. הקובץ קורא את הסמן החי ב-`node_modules/.open-slide/current.json`. **קראו אותו מחדש בכל תור דייקטי**; ערך שקראתם מקודם כמעט תמיד כבר לא עדכני.

### הערות המרצה נכתבות ב-<bdi>notes</bdi>, אף פעם לא בקובץ markdown

כשמבקשים תסריט הרצאה, סוכנים כותבים כמעט תמיד <bdi>script.md</bdi> שהרנטיים בכלל לא קורא, ותצוגת המרצה נשארת ריקה.

ההערות הן ייצוא <bdi>notes</bdi> אופציונלי בתוך <bdi>slides/&lt;id&gt;/index.tsx</bdi>, **מיושר לפי אינדקס** למערך העמודים שמיוצא כברירת מחדל. <bdi>SlideModule</bdi> מגדיר אותו כ-<bdi>notes?: (string | undefined)[]</bdi>. כדי לדלג על עמוד השתמשו ב-<bdi>undefined</bdi> במקום להזיז את המערך:

```tsx
const Cover: Page = () => <div dir="rtl">שלום</div>;
const Agenda: Page = () => <div dir="rtl">סדר היום</div>;
const Pillars: Page = () => <div dir="rtl">שלושה עמודי תווך</div>;

export const notes: (string | undefined)[] = [
  'פתחו בציטוט של הלקוח, ואז הציגו את עצמכם.',
  undefined,
  `שלושה עמודי תווך, פסקה לכל אחד.
עצרו לשאלות לפני המעבר.`,
];

export default [Cover, Agenda, Pillars];
```

כללים:

- ערך אחד לכל עמוד, באותו סדר של ייצוא ברירת המחדל. ערך חסר מזיז בשקט את כל ההערות שאחריו.
- הערות מרובות שורות עובדות, השתמשו ב-template literal.
- **הייצוא <bdi>notes</bdi> חייב להיות מערך ליטרלי שנכתב ידנית, עם איבר פשוט אחד לכל עמוד, ובלי <bdi>satisfies</bdi> או <bdi>as const</bdi> אחריו.** שרת הפיתוח כותב עריכות מהמגירה בחזרה לתוך הקוד (<bdi>PUT /__notes</bdi>). מערך מחושב, קבוע מיובא או <bdi>.map()</bdi> מחזירים <bdi>422</bdi> ושוברים את העריכה מהמגירה. spread בתוך הליטרל (<bdi>[...intro, 'x']</bdi>) גרוע יותר: הוא עובר את הבדיקה, נספר כאיבר אחד, ועריכה מהמגירה נוחתת בשקט על העמוד הלא נכון.
- **תצוגת המרצה מרנדרת תת-קבוצה קטנה של Markdown** (מודגש, נטוי, קוד, כותרות `#`, רשימות) מאז <bdi>2.0.0</bdi>; המגירה עורכת את הטקסט הגולמי. הסקיל <bdi>slide-authoring</bdi> המקורי עדיין אומר ש-markdown לא מרונדר, וזה כבר לא תואם את הקוד. כל שורת הערה שמתחילה ב-`- `, `* `, `1. ` או `1) ` הופכת לרשימה.
- **הערות בעברית מיושרות ל-LTR ואי אפשר לתקן את זה מתוך השקף.** המגירה ותצוגת המרצה לא מגדירות <bdi>dir</bdi>, ורשימות בתצוגת המרצה מוזחות עם ריפוד פיזי משמאל, כך שהתבליטים העבריים יושבים בצד שמאל. בהערות בעברית העדיפו פסקאות קצרות ופשוטות על פני רשימות Markdown.
- אף פעם אל תמסרו תסריט הרצאה כקובץ נפרד. אם המשתמש מבקש "תסריט" או "הערות מרצה", זה נכנס לייצוא הזה.

המקור מתעד את הייצוא הזה מאז <bdi>2.0.0</bdi>; ההתנהגות בעברית שלמעלה והתנהגות הייצוא שלמטה לא מתועדות בשום מקום במקור.

### ייצוא מצגת בעברית (קראו לפני "תייצא את זה להנהלה")

בתפריט ה-<bdi>Download</bdi> בסרגל הכלים יש ארבעה ייצואים. נבדק על <bdi>2.3.1</bdi> על ידי ייצוא מצגת בדיקה בעברית וקריאת הקבצים שנוצרו:

| ייצוא | התוצאה בעברית | הערות מרצה בפנים? |
| --- | --- | --- |
| **<bdi>Export as PPTX</bdi>** (ניתן לעריכה) | **שבור לעברית. אל תשתמשו.** כל פסקה עברית שנשברת לכמה שורות, או שמערבבת עברית עם קטע לועזי, מפוצלת לריצת טקסט אחת לכל תו עם ירידת שורה אחרי כל אחת, כך ש-PowerPoint מציג טור אנכי של אותיות בודדות. אנגלית מיוצאת תקין; התקלה ספציפית ל-RTL. בנוסף הפסקאות לא מקבלות מאפיין <bdi>rtl</bdi>, ו-<bdi>text-align: start</bdi> ממופה לשמאל. | כן |

| **<bdi>Export as PDF</bdi>** | בטוח, טקסט וקטורי דרך מנגנון ההדפסה של הדפדפן. לא נתמך ב-Safari (מוצגת שגיאה); השתמשו ב-Chrome או Edge. מסגרת ההדפסה לבנה: שכבות <bdi>gradient</bdi> ב-CSS ו-<bdi>box-shadow</bdi> מוסרות מכל אלמנט, כך שרקע עמוד שהוא רק גרדיאנט יודפס לבן. שימו <bdi>background-color</bdi> מוצק מתחת לכל גרדיאנט, ובדקו את ה-PDF. | לא |

**הסוכן לא יכול להפיק את הקובץ בעצמו.** הייצוא רץ בדפדפן; ל-CLI אין פקודת ייצוא, ו-PDF פותח את חלון ההדפסה של המערכת. מסרו למשתמש את השלבים: להפעיל את שרת הפיתוח, לפתוח את המצגת ב-Chrome או Edge, <bdi>Download</bdi>, <bdi>Export as PDF</bdi>, ואז לבחור "שמירה כ-PDF" כיעד (גודל הדף כבר מוגדר). לעולם אל תטענו ש-<bdi>npm run build</bdi> הפיק את הקובץ להנהלה.

עמוד ה-Export בתיעוד הרשמי עדיין אומר ש-PPTX ניתן לעריכה "עוד לא זמין", וזה כבר לא תואם את התפריט בפועל.

### תזכורת לתקציב האנכי (גורם ה-#1 לשקפים שבורים)

כל מה שמתחת ל-1080px בקאנבס נחתך בשקט. לפני כתיבת כל עמוד, חשבו:

```
(font_size × line_height × number_of_lines) + gaps + (2 × padding) ≤ 1080
```

אם צפוף, **פצלו לשני עמודים**. לעולם אל תשתמשו ב-`overflow: auto/scroll/hidden`, שוליים שליליים, או טרנספורמים כדי להסתיר overflow. הקאנבס לא גולל; תוכן שנחתך הולך לאיבוד. ראו [./rules/slide-authoring.md](./rules/slide-authoring.md) סעיף "תקציב אנכי" לדוגמה המלאה.

לטקסט עברי, אל תסמכו על גדלים שנלקחו מפריסה באנגלית: כותרת שיושבת על שורה אחת באנגלית יכולה לעבור לשתיים ב-Heebo. הקטינו את הגודל או קצרו את הטקסט, ואשרו בנתיב התצוגה המקדימה. ראו `hebrew-rtl.md` בפרק 4.

## שרתי MCP מומלצים

אין ישירות, מכיוון של-open-slide אין API. הסקיל הזה הוא הנחיה לכתיבה בצד הלקוח בלבד.

## מלכודות נפוצות

אלה צורות הכישלון ש-coding agent נתקל בהן כשהוא בונה מצגת ב-open-slide בעברית בלי הסקיל הזה. אלו לא טעויות של המשתמש.

1. **שימוש ב-`paddingLeft` ו-`marginLeft` בכל מקום.** ב-LTR אלו "מהתחלת השורה". ב-RTL הם פיזית בצד הלא נכון של הקאנבס. השתמשו ב-`paddingInlineStart` / `paddingInlineEnd` (או הקיצור `paddingInline`) כדי שהלאיאוט יתהפך אוטומטית כש-`dir="rtl"` מוגדר על שורש הקאנבס. אותו עיקרון על `left` / `right` (השתמשו ב-`insetInlineStart` / `insetInlineEnd`) ו-`text-align: left/right` (השתמשו ב-`text-align: start/end`).

2. **הגדרת `direction: 'rtl'` על `<html>` או גלובלית.** השורש של הקאנבס ב-open-slide הוא רכיב הדף, לא מסמך ה-HTML. ה-chrome של שרת הפיתוח (מסילת הקבצים, חיצי הניווט) הוא UI מקורי באנגלית; היפוך כיוון המסמך שובר אותו. הגדירו `dir="rtl"` רק על `<div>` השורש של רכיב הדף. האינספקטור ומצב המגיש שומרים על LTR; רק התוכן שלכם מתהפך. גם אין אפשרות להעביר אותם לעברית: `OpenSlideConfig.locale` סומן כמיושן לטובת מתג השפה בממשק, ושפות הממשק שנשלחות הן `en`, `zh-TW`, `zh-CN`, `ja` ו-`es` בלבד. אמרו למשתמש שממשק הכתיבה נשאר באנגלית, ורק המצגת עצמה בעברית.

3. **קריאה לתיקיית השקף בשם עברי.** זה הדבר הטבעי לעשות במצגת בעברית, וזה מאבד את השקף בשקט: מנגנון הגילוי מסנן שמות תיקיות דרך `/^[a-z0-9_-]+$/i` ורק מדפיס אזהרה. מזהה באנגלית ב-kebab-case, והעברית ב-`meta.title`. ראו "מזהי תיקיות השקפים חייבים להיות באנגלית" למעלה.

4. **טעינת הפונט העברי מתוך רכיב העמוד.** בלוק `<style>@import ...</style>` או `<link>` שמרונדר בתוך `Page` רושם מחדש את כל סט ה-`@font-face` פעם אחת לכל עמוד שמורכב, ועמוד הבית, מסילת התמונות הממוזערות, תצוגת הרשת וה-root של הדפסת ה-PDF מרכיבים את כל העמודים בו-זמנית. הכלל במקור הוא להזריק את גיליון הסגנון פעם אחת ל-`<head>` מרמת המודול של `index.tsx`, עם מזהה אלמנט שקשור לשקף (`osd-webfont-<slide-id>`) כדי שהפונטים של שקף אחד לא יחסמו את של האחרים. ראו את `hebrew-rtl.md` בפרק 3.

5. **פונט ברירת המחדל ל-display הוא סריף בלי אותיות עבריות.** <bdi>defaultDesign.fonts.display</bdi> הוא <bdi>Georgia, "Times New Roman", serif</bdi> ו-<bdi>fonts.body</bdi> הוא <bdi>-apple-system, BlinkMacSystemFont, "Inter", system-ui, sans-serif</bdi>. ל-Georgia אין גליפים עבריים, ולכן כותרת עברית ללא עיצוב נופלת בשקט לסריף מערכתי כלשהו (מסוג David או Times). זו הסיבה האמיתית לתסמין "המצגת שלי בעברית נראית בסריף מיושן", ולא ה-stack של ה-body. למצגות שמיועדות לקהל מעבר למחשב הפיתוח, טענו Heebo או Rubik דרך Google Fonts (דרך <bdi>css2</bdi>, בלי פרמטר <bdi>subset</bdi>, הוא ממילא לא נקרא) ושימו אותם ראשונים ב-stack עם הפונטים המערכתיים כ-fallback. ראו `hebrew-rtl.md`.

6. **שימוש בסקאלת הטיפוגרפיה של האנגלית בלי בדיקה.** גדלים שכוונו לטקסט באנגלית לא עוברים כמו שהם: שורות עבריות תופסות רוחב אחר, ושורה מתורגמת היא באורך אחר. בדקו כל עמוד עברי בתצוגה מקדימה. אם ה-hero נראה קטן, ההגדלה ב-10-15% שבפרק 4 של `hebrew-rtl.md` היא נקודת פתיחה עריכתית, אבל חשבו מחדש את התקציב האנכי אחרי כל הגדלה, כי הגדלה עלולה ליצור בדיוק את שבירת השורה שהיא נועדה למנוע.

7. **ערבוב עברית ולועזית בלי בידוד.** משפט כמו "השתמשו ב-React Router" שמערבב תווים עבריים ולטיניים מרנדר את הפיסוק במקום הלא נכון, כי האלגוריתם הדו-כיווני של הדפדפן לא תמיד מבדל את הריצה הלטינית. בודדו את הריצה עם <bdi>&lt;span dir="ltr"&gt;</bdi> (מועדף ב-<bdi>2.x</bdi>, ראו מלכודת 14) או עם `<bdi>`: <bdi>השתמשו ב-&lt;span dir="ltr"&gt;React Router&lt;/span&gt;</bdi>. קריטי למזהי קוד, שמות מותגים, ו-URL בתוך טקסט עברי.

8. **שימוש ב-`array.map` לרכיבים חזותיים חוזרים.** הכלל המקורי (רכיב אחד שמתממש פר פריט, לא `map` על מערך נתונים) חל גם בעברית. הסיבה היא האינספקטור: `map` חולק מקור JSX אחד פר פריט, אז עריכת תווית עברית אחת תשנה את כל הכרטיסיות שמתרנדרות. הגדירו `<Card />` פעם אחת, וצרו אותה שלוש פעמים במפורש. ראו `slide-authoring.md`.

9. **התעלמות מ-`node_modules/.open-slide/current.json`.** כשהמשתמש אומר "תקן את הכותרת בעמוד הזה", הדייקטיב "הזה" ממופה בדיוק כמו ה-"this" באנגלית, אתם חייבים לקרוא את `current.json` כדי למצוא על איזה שקף הוא נמצא. קראו מחדש בכל תור. ראו `current-slide.md`.

10. **תקציב אנכי בסקאלה המוגדלת לעברית.** שקף שמתאים לכותרת על שלוש שורות בגובה 200px ב-LTR (3 × 200 × 0.95 = 570px) יחרוג מ-1080 אם תשמרו על שלוש שורות ותגדילו ל-232px לעברית (3 × 232 × 0.95 = 661px), ברגע שמוסיפים padding וכותרת משנה, עוברים את הגבול. או הצמידו לשורה אחת או שתיים בעברית, או חשבו מחדש את כל התקציב עם הערכים המוגדלים לפני שאתם מתחייבים. פיצול הוא תמיד התשובה הנכונה.

11. **מונחים טכניים שתורגמו לא נכון בתוך תוכן השקף.** סוכנים מתרגמים מונחי פיתוח לעברית שמשמעותה אחרת ("themes" כ"ערכאות", מונח משפטי; "resolution" כ"רזולוציה"). השתמשו במילון שב-`hebrew-rtl.md` בפרק 6.5, ואמתו מונחים מול דובר ילידי לפני שאתם שולחים החוצה.

12. **גרדיאנט בין צבעי מותג.** גרדיאנט בין שני גוונים רחוקים של המותג עובר דרך גוון ביניים שאינו במותג (כחול למג'נטה עובר דרך סגול). השאירו את צבעי המותג הראשיים מוצקים; ראו `hebrew-rtl.md` בפרק 7.5. זכרו גם שייצוא ל-PDF מסיר גרדיאנטים של CSS.

13. **בדקו את הטקסט שלכם עצמכם ב-bidi. גם בסקיל הזה.** סקיל שמזהיר על `<bdi>` חסר יפספס את ה-`<bdi>` שלו עצמו בתוך משפטים כמו "השתמשו ב-RTL" שאמור להיות "השתמשו ב-`<bdi>`RTL`</bdi>`". כשאתם כותבים טקסט, שקפים, או דוגמאות, סרקו ידנית כל מילה לטינית בתוך טקסט עברי ובודדו אותה (<bdi>&lt;span dir="ltr"&gt;</bdi> או `<bdi>`). מזהי קוד, שמות מותגים, גרסאות, סיומות קבצים, כולם צריכים בידוד. מי שכותב את הכלל לא פטור מהכלל.

14. **התגית <bdi>&lt;bdi&gt;</bdi> מבטלת עריכת טקסט במקום לכל השורה שלה.** ב-<bdi>2.x</bdi>, עריכה בלחיצה כפולה מתייחסת לאלמנט כטקסט ניתן לעריכה רק כשכל הילדים שלו הם טקסט, <bdi>&lt;br&gt;</bdi>, או אחת מהתגיות <bdi>b code del em i ins mark s small span strong sub sup u</bdi>. התגית <bdi>bdi</bdi> לא ברשימה, ולכן את <bdi>&lt;p&gt;השתמשו ב-&lt;bdi&gt;React Router&lt;/bdi&gt;&lt;/p&gt;</bdi> כבר אי אפשר לערוך במקום. כשהמשתמש רוצה להמשיך לערוך בדפדפן, השתמשו ב-<bdi>&lt;span dir="ltr"&gt;React Router&lt;/span&gt;</bdi>: כללי הרינדור של HTML נותנים לכל אלמנט עם מאפיין <bdi>dir</bdi> את <bdi>unicode-bidi: isolate</bdi>, ו-<bdi>dir="ltr"</bdi> גם קובע את כיוון הריצה, ויחד זה שקול למה ש-<bdi>&lt;bdi&gt;</bdi> עושה לריצה לטינית (<bdi>unicode-bidi: isolate</bdi> לבד, בלי <bdi>dir</bdi>, לא מספיק: הוא עדיין מציג <bdi>-5</bdi> כ-<bdi>5-</bdi>), ו-<bdi>span</bdi> נשאר ניתן לעריכה. השתמשו ב-<bdi>&lt;span dir="ltr"&gt;</bdi> גם למספרים עם סימן.

15. **פאנל Format ופאנל Design מבטלים כללי עברית.** כפתורי היישור בפאנל Format כותבים <bdi>textAlign: 'right'</bdi> פיזי ומתייחסים ל"שמאל" כאל "הסר את המאפיין"; כפתור ה-Shuffle בפאנל Design מחליף את ה-<bdi>design</bdi> בפריסט לטיני בלבד, ומוחק את Heebo ואת סקאלת הטיפוגרפיה. אחרי שמשתמש נוגע באחד הפאנלים, בדקו שוב בקוד את <bdi>textAlign</bdi>, <bdi>fonts.display</bdi> ו-<bdi>typeScale</bdi>. הפירוט בפרקים 2 ו-3 של `hebrew-rtl.md`.

16. **בחירה ב-<bdi>Export as PPTX</bdi> למצגת בעברית.** הייצוא ל-PPTX הניתן לעריכה מפרק עברית שנשברת לשורות או מעורבבת לתו אחד בכל שורה. השתמשו ב-<bdi>Export as image PPTX</bdi> או ב-PDF; ראו "ייצוא מצגת בעברית" למעלה.

17. **אירוח עצמי של פונט עברי דרך חיפוש Google Fonts בפאנל הנכסים.** ההורדה מביאה קובץ TTF יחיד בלי תת-הקבוצה העברית; עבור Heebo בקובץ יש 0 מתוך 27 האותיות העבריות, בזמן שהתצוגה המקדימה בחיפוש מציגה עברית תקינה. טענו משפחות עבריות בהזרקה ל-head (פרק 3 ב-`hebrew-rtl.md`) או ארחו קובץ שבדקתם שיש בו גליפים עבריים.
