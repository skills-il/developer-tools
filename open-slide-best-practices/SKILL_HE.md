# שיטות עבודה ב-open-slide למפתחים ישראלים

> מבוסס על [1weiho/open-slide](https://github.com/1weiho/open-slide) (MIT). התאמות עברית ו-RTL על ידי [skills-il](https://agentskills.co.il).

## בעיה

open-slide מגיע עם מערכת כתיבה ייחודית: קאנבס קבוע 1920×1080 מבוסס React, אובייקט DesignSystem עם טיפוסים, תיקיית themes, אינספקטור שמטמיע סמני `@slide-comment` בקוד המקור, וחמש סקילים מובנות (`slide-authoring`, `create-slide`, `create-theme`, `apply-comments`, `current-slide`). אף אחת מהן לא נוגעת בעברית או ב-RTL. בלי הסקיל הזה, מצגת שאיג'נט כותב יוצאת מיושרת לשמאל, עם פונטים מערכתיים בלבד, `paddingLeft` שדוחף את הטקסט לכיוון הלא נכון, ובלי שום הנחיה לערבוב עברית ולועזית. מפתחים ישראלים מבזבזים שעות על התאמת RTL בדיעבד, על טעינת פונטים עבריים מ-Google Fonts, ועל גילוי שסקאלת הטיפוגרפיה (140-200px לכותרת ראשית) שמתאימה ל-Inter יוצאת צפופה ב-Heebo באותו גודל.

## הוראות

### מתי להשתמש

השתמשו בסקיל הזה כל פעם שאתם כותבים או עורכים קוד ב-`slides/<id>/` בפרויקט open-slide, יוצרים ערכת נושא ב-`themes/`, או מעבדים הערות מהאינספקטור, ובמיוחד אם התוכן בעברית או דו-לשוני.

### יצירת פרויקט חדש

בתיקייה ריקה או בסביבת עבודה ללא פרויקט open-slide קיים, צרו אחד עם:

```bash
npx @open-slide/cli init my-slide
cd my-slide
npm run dev
```

החליפו את `my-slide` בשם פרויקט מתאים. הסקאפולדר מתקין את התלויות עם npm ומדפיס `npm run dev` כשלב הבא; גם `pnpm dev` עובד אם תתקינו מחדש עם pnpm.

**גרסת <bdi>Node</bdi>.** החבילה `@open-slide/cli` תלויה ב-`commander@15` שמצהיר `"node": ">=22.12.0"`, וב-`chalk@6` (`">=22"`). על <bdi>Node 20</bdi> ההתקנה עדיין מסתיימת, אבל npm מדפיס `EBADENGINE Unsupported engine` לשתיהן. השתמשו ב-<bdi>Node 22.12</bdi> ומעלה.

מה שהסקאפולד נותן לכם:

| נתיב | מה זה |
| --- | --- |
| `slides/<id>/index.tsx` | תיקייה אחת לכל שקף. ראו את כלל המזהה למטה. |
| `themes/` | קבצי ערכות נושא ב-markdown |
| `open-slide.config.ts` | ייצוא מטיפוס `OpenSlideConfig`, ריק כברירת מחדל. ההגדרות ברמת הפריימוורק יושבות כאן: `base`, `slidesDir`, `themesDir`, `assetsDir`, `port`, `allowedHosts`, `build`, ו-`locale` שסומן כמיושן. |
| `.agents/skills/` ו-`.claude/skills/` | חמשת הסקילים המקוריים, מועתקים פנימה בזמן ה-init |
| `npm run sync:skills` | מעתיק מחדש את הסקילים המצורפים מתוך `@open-slide/core` אחרי שדרוג |

הריצו `npm run sync:skills` אחרי כל שדרוג של `@open-slide/core`, אחרת הסוכן ממשיך לקרוא את עותקי הסקילים מהגרסה שאיתה יצרתם את הפרויקט.

### מזהי תיקיות השקפים חייבים להיות באנגלית (שמות בעברית נזרקים בשקט)

**אל תקראו לתיקיית שקף בעברית.** מנגנון הגילוי מסנן כל תיקייה תחת `slides/` דרך `SLIDE_ID_RE = /^[a-z0-9_-]+$/i` ומדלג על השאר, כך שתיקייה כמו `slides/פתיחה/` לא מגיעה לסרגל הצד, לדפדפן, או ל-build. נבדק על <bdi>@open-slide/core@1.18.0</bdi>:

```
[plugin:open-slide] [plugin open-slide] Ignoring slide folder "פתיחה": slide ids must match
/^[a-z0-9_-]+$/i (lowercase/uppercase letters, digits, "-", "_"). Rename the folder under
"slides/" to a kebab-case id so it appears in the browser and can be moved into folders.
```

זו אזהרה בלבד ולא שגיאה, ולכן `npm run build` מסתיים בהצלחה וקל מאוד לפספס את השקף החסר. השתמשו במזהה באנגלית ב-kebab-case (`peticha`, `cover`, `q2-roadmap`), ושימו את העברית ב-`meta.title` ובתוכן העמוד, איפה שהיא שייכת.

**אל תחילו את הכלל הזה יותר מדי רחב.** הוא ספציפי למזהי תיקיות של שקפים. נבדק ואינו מושפע:

| משטח | עברית מותרת? | למה |
| --- | --- | --- |
| שם התיקייה `slides/<id>/` | לא | מסונן על ידי `SLIDE_ID_RE` בשלב הגילוי |
| `meta.title` | כן | טקסט חופשי, אף פעם לא משמש כמזהה |
| שם הקובץ `themes/<id>.md` | כן | מזהה ערכת הנושא הוא `path.basename(file, '.md')` בלי שום סינון ASCII, והנתיבים נבנים עם `encodeURIComponent(id)` |
| ערכים ב-frontmatter של ערכת נושא (`name:`, `description:`) | כן | רק המפתח ב-frontmatter נבדק מול `/^([A-Za-z0-9_-]+)\s*:/`; הערך הוא טקסט חופשי |
| תוכן השקף עצמו | כן | זה סתם טקסט ב-JSX |

### עברית ו-RTL

לכל מצגת בעברית או דו-לשונית, טענו קודם את [./rules/hebrew-rtl.md](./rules/hebrew-rtl.md). הוא מכסה:

- פונטים עבריים מ-Google Fonts (Heebo, Rubik, Assistant, Noto Sans Hebrew) עם `subset=hebrew`
- הגדרת `dir="rtl"` הנכונה ברמת רכיב הדף, ולא על `<html>` (אחרת ה-chrome של שרת הפיתוח נשבר)
- מאפייני CSS לוגיים (`paddingInlineStart`, `marginInlineStart`, `insetInlineStart`) במקום `paddingLeft`/`marginLeft`/`left`
- `flexDirection: 'row-reverse'` מול הגדרת `dir` על הקונטיינר הפלקס
- טקסט דו-כיווני עם `<bdi>` לערבוב עברית עם לועזית (שמות מותגים, קוד, URL)
- כוונון סקאלת טיפוגרפיה לעברית (עברית רחבה ב-10-15% פר תו באותו גודל בפיקסלים)
- בחירת `DesignSystem.fonts.display` ו-`fonts.body` עבריים שמתאימים לגודל hero
- דפוסי ערכת נושא ב-`themes/` שמתאימים ל-RTL
- מלכודות טיפוגרפיות בעברית: רנדור של ניקוד, מרווחי אותיות סופיות, מקף רגיל לעומת מקף יהודי (maqaf)

### כתיבת שקפים (מבנה הקובץ, קאנבס, סקאלת טיפוגרפיה, ערכות נושא, טוקני עיצוב)

לתיעוד הטכני המלא של מה שנכנס ל-`slides/[id]/index.tsx`, טענו את [./rules/slide-authoring.md](./rules/slide-authoring.md). זה אותו תוכן שמופיע בסקיל המקורי `slide-authoring`, עם הערות עברית/RTL בתוך הטקסט. הוא מכסה את מבנה הקובץ, חישובי הקאנבס של 1920×1080, סקאלת הטיפוגרפיה, מרווחים, כיוון חזותי, ערכות נושא, אובייקט הטוקנים `DesignSystem`, תבנית הבסיס, נכסים (assets), image placeholders, וכלל הרכיבים החוזרים.

מאז, הפרויקט המקורי פיצל את סקיל ה-`slide-authoring` שלו לקבצי reference נפרדים לכל פרימיטיב. שלושה מהם מכסים פרימיטיבים שהסקיל הזה לא משכפל, קראו אותם במקור במקום לממש ביד:

| קובץ ה-reference במקור | הפרימיטיב | למה זה משנה במצגת בעברית |
| --- | --- | --- |
| [`references/steps.md`](https://raw.githubusercontent.com/1weiho/open-slide/main/packages/core/skills/slide-authoring/references/steps.md) | חשיפה מדורגת עם `<Steps>` / `<Step>` | חשיפה מדורגת מאפשרת לשמור כל פסקה עברית קצרה במקום להעמיס עמוד אחד צפוף |
| [`references/page-numbers.md`](https://raw.githubusercontent.com/1weiho/open-slide/main/packages/core/skills/slide-authoring/references/page-numbers.md) | ה-hook בשם `useSlidePageNumber()` | קראו `{ current, total }` מה-hook במקום לקודד מונה בפוטר; עטפו את הספרות הלטיניות ב-`<bdi>` בתוך פוטר RTL |
| [`references/morph.md`](https://raw.githubusercontent.com/1weiho/open-slide/main/packages/core/skills/slide-authoring/references/morph.md) | מעברי אלמנט משותף עם `MorphElement` ("magic move") | ה-morph מבצע אינטרפולציה של מיקום וגודל לאורך המעבר, ולכן אלמנט שזז בין עמוד LTR לעמוד RTL צריך אותו `id` בשניהם |

### כתיבת מצגת חדשה

כשהמשתמש מבקש "תכין שקפים על X" / "תיצור מצגת" / "תכין דק", טענו את [./rules/create-slide.md](./rules/create-slide.md) לזרימת העבודה: בחירת ערכת נושא, ארבע שאלות מנחות (כיוון אסתטי, מספר עמודים, צפיפות טקסט, תנועה), בחירת מזהה לשקף, תכנון מבני, החלטה על הכיוון החזותי, כתיבה, סקירה עצמית, ומסירה למשתמש.

### יצירת ערכת נושא

כשהמשתמש מבקש "תיצור ערכת נושא" / "תכין תמה בשם X" / "תוציא ערכת נושא מהשקף הזה", טענו את [./rules/create-theme.md](./rules/create-theme.md). כל ערכת נושא היא קובץ markdown יחיד תחת `themes/<id>.md` עם סעיפי פלטה / טיפוגרפיה / לאיאוט / רכיבים קבועים / תנועה / אסתטיקה.

### החלת הערות מהאינספקטור

כשהמשתמש לחץ על עמוד שמתרנדר בשרת הפיתוח והוסיף הערות (דרך כלי האינספקטור בדפדפן), ומבקש "תחיל את ההערות" / "תעבד את ההערות שעל השקף", טענו את [./rules/apply-comments.md](./rules/apply-comments.md). הקובץ מכסה את הפורמט של הסמן `{/* @slide-comment */}`, את ה-regex לזיהוי, את ה-payload ה-base64url המפוענח, ואת הסדר הנכון להחלת השינויים (משורה אחרונה לראשונה).

### פיענוח הפניות דייקטיות ("העמוד הזה", "השקף שאני נמצא עליו")

כשהמשתמש מתייחס לשקף הנוכחי בלי לקרוא לו בשם, טענו את [./rules/current-slide.md](./rules/current-slide.md) **קודם**. הקובץ מסביר איך לקרוא את הסמן החי ב-`node_modules/.open-slide/current.json`, אילו שדות יש בו, וכללי טריות. **קראו אותו מחדש בכל תור דייקטי** — המשתמש מנווט בין תורים, אז ערך שקראתם מקודם כמעט תמיד כבר לא עדכני.

### תזכורת לתקציב האנכי (גורם ה-#1 לשקפים שבורים)

כל מה שמתחת ל-1080px בקאנבס נחתך בשקט. לפני כתיבת כל עמוד, חשבו:

```
(font_size × line_height × number_of_lines) + gaps + (2 × padding) ≤ 1080
```

אם צפוף, **פצלו לשני עמודים**. לעולם אל תשתמשו ב-`overflow: auto/scroll/hidden`, שוליים שליליים, או טרנספורמים כדי להסתיר overflow. הקאנבס לא גולל; תוכן שנחתך הולך לאיבוד. ראו [./rules/slide-authoring.md](./rules/slide-authoring.md) סעיף "תקציב אנכי" לדוגמה המלאה.

לטקסט עברי התקציב צפוף יותר ממה שנראה: עברית רחבה ב-10-15% פר תו באותו גודל, אז כותרת שיושבת על שורה אחת באנגלית בגובה 80px יכולה לעבור לשתיים ב-Heebo. או הקטינו את הגודל או קצרו את הטקסט. ראו `hebrew-rtl.md` לטבלת הכיול.

## שרתי MCP מומלצים

אין ישירות, מכיוון של-open-slide אין API. הסקיל הזה הוא הנחיה לכתיבה בצד הלקוח בלבד.

## מלכודות נפוצות

אלה צורות הכישלון ש-coding agent נתקל בהן כשהוא בונה מצגת ב-open-slide בעברית בלי הסקיל הזה. אלו לא טעויות של המשתמש.

1. **שימוש ב-`paddingLeft` ו-`marginLeft` בכל מקום.** ב-LTR אלו "מהתחלת השורה". ב-RTL הם פיזית בצד הלא נכון של הקאנבס. השתמשו ב-`paddingInlineStart` / `paddingInlineEnd` (או הקיצור `paddingInline`) כדי שהלאיאוט יתהפך אוטומטית כש-`dir="rtl"` מוגדר על שורש הקאנבס. אותו עיקרון על `left` / `right` (השתמשו ב-`insetInlineStart` / `insetInlineEnd`) ו-`text-align: left/right` (השתמשו ב-`text-align: start/end`).

2. **הגדרת `direction: 'rtl'` על `<html>` או גלובלית.** השורש של הקאנבס ב-open-slide הוא רכיב הדף, לא מסמך ה-HTML. ה-chrome של שרת הפיתוח (מסילת הקבצים, חיצי הניווט) הוא UI מקורי באנגלית; היפוך כיוון המסמך שובר אותו. הגדירו `dir="rtl"` רק על `<div>` השורש של רכיב הדף. האינספקטור ומצב המגיש שומרים על LTR; רק התוכן שלכם מתהפך. גם אין אפשרות להעביר אותם לעברית: `OpenSlideConfig.locale` סומן כמיושן לטובת מתג השפה בממשק, ושפות הממשק שנשלחות הן `en`, `zh-TW`, `zh-CN` ו-`ja` בלבד. אמרו למשתמש שממשק הכתיבה נשאר באנגלית, ורק המצגת עצמה בעברית.

3. **קריאה לתיקיית השקף בשם עברי.** זה הדבר הטבעי לעשות במצגת בעברית, וזה מאבד את השקף בשקט: מנגנון הגילוי מסנן שמות תיקיות דרך `/^[a-z0-9_-]+$/i` ורק מדפיס אזהרה. מזהה באנגלית ב-kebab-case, והעברית ב-`meta.title`. ראו "מזהי תיקיות השקפים חייבים להיות באנגלית" למעלה.

4. **טעינת הפונט העברי מתוך רכיב העמוד.** בלוק `<style>@import ...</style>` או `<link>` שמרונדר בתוך `Page` רושם מחדש את כל סט ה-`@font-face` פעם אחת לכל עמוד שמורכב, ועמוד הבית, מסילת התמונות הממוזערות, תצוגת הרשת וה-root של הדפסת ה-PDF מרכיבים את כל העמודים בו-זמנית. הכלל במקור הוא להזריק את גיליון הסגנון פעם אחת ל-`<head>` מרמת המודול של `index.tsx`, עם מזהה אלמנט שקשור לשקף (`osd-webfont-<slide-id>`) כדי שהפונטים של שקף אחד לא יחסמו את של האחרים. ראו את `hebrew-rtl.md` בפרק 3.

5. **רק stack של פונטים מערכתיים.** התבנית המקורית משתמשת ב-`system-ui, -apple-system, sans-serif` הן ל-display והן ל-body. ב-macOS זה מתורגם ל-Helvetica / SF Pro לעברית, שזה עובד אבל לא ברמת display בגדלים של 140-200px. למצגות שמיועדות לקהל מעבר למחשב הפיתוח, טענו Heebo או Rubik דרך Google Fonts (`?subset=hebrew`) ושימו אותם ראשונים ב-stack עם הפונטים המערכתיים כ-fallback. ראו `hebrew-rtl.md`.

6. **אותה סקאלת טיפוגרפיה כמו באנגלית.** 140-200px hero ב-Inter יוצא צפוף בקצה התחתון (140) לעברית, כי הגובה של אותיות עבריות יושב בגובה ה-cap-height של פונטים לטיניים עם x-height גדול. עברית ב-140px נקראת כמו לטינית ב-120px. או הגדילו את ה-hero ל-160-220px לעברית, או הורידו את מספר השורות.

7. **ערבוב עברית ולועזית בלי `<bdi>`.** משפט כמו "השתמשו ב-React Router" שמערבב תווים עבריים ולטיניים מרנדר את הפיסוק במקום הלא נכון, כי האלגוריתם הדו-כיווני של הדפדפן לא תמיד מבדל את הריצה הלטינית. עטפו את הריצה הלטינית ב-`<bdi>`: `השתמשו ב-<bdi>React Router</bdi>`. קריטי למזהי קוד, שמות מותגים, ו-URL בתוך טקסט עברי.

8. **`array.map` לרכיבים חזותיים חוזרים.** הכלל המקורי (רכיב אחד שמתממש פר פריט, לא `map` על מערך נתונים) חל גם בעברית. הסיבה היא האינספקטור: `map` חולק מקור JSX אחד פר פריט, אז עריכת תווית עברית אחת תשנה את כל הכרטיסיות שמתרנדרות. הגדירו `<Card />` פעם אחת, וצרו אותה שלוש פעמים במפורש. ראו `slide-authoring.md`.

9. **התעלמות מ-`node_modules/.open-slide/current.json`.** כשהמשתמש אומר "תקן את הכותרת בעמוד הזה", הדייקטיב "הזה" ממופה בדיוק כמו ה-"this" באנגלית, אתם חייבים לקרוא את `current.json` כדי למצוא על איזה שקף הוא נמצא. קראו מחדש בכל תור. ראו `current-slide.md`.

10. **תקציב אנכי בסקאלה המוגדלת לעברית.** שקף שמתאים לכותרת על שלוש שורות בגובה 200px ב-LTR (3 × 200 × 0.95 = 570px) יחרוג מ-1080 אם תשמרו על שלוש שורות ותגדילו ל-232px לעברית (3 × 232 × 0.95 = 661px) — ברגע שמוסיפים padding וכותרת משנה, עוברים את הגבול. או הצמידו לשורה אחת או שתיים בעברית, או חשבו מחדש את כל התקציב עם הערכים המוגדלים לפני שאתם מתחייבים. פיצול הוא תמיד התשובה הנכונה.

11. **מונחים טכניים שתורגמו לא נכון בתוך תוכן השקף.** שירותי תרגום וסוכני AI נופלים בעברית טכנית. מלכודות נפוצות:
   - **"themes" → "ערכאות"** (זה מונח משפטי שמשמעותו 'בתי משפט'). נכון: **"ערכות נושא"** או **"תמות"**.
   - **"resolution" (במשמעות פתרון של הפניה) → "רזולוציית"** (זה גודל מסך/תמונה). נכון: **"פיענוח"** או **"זיהוי"**.
   - **"authoring" → "אוטרינג"** (תעתיק אנגלי שנשמע מוזר). נכון: **"כתיבה"** או **"יצירה"**.
   - **"tuned scale" → "סקאלה מכוונת"** (תרגום מילולי שנשמע רובוטי). עדיף: **"סקאלה מותאמת"**.
   תמיד אמתו מונחים טכניים בעברית מול דובר ילידי או מול קהילת המפתחים בעברית לפני שאתם שולחים החוצה.

12. **שילוב צבעי מותג כגרדיאנט יוצר גוון ביניים שאינו במותג.** גרדיאנט לינארי מ-Israeli Blue (`#003286`) ל-YooTech Magenta (`#bc46a2`) עובר דרך סגול רווי — שלא קיים בפלטה של agentskills.co.il. אם לפרויקט יש פלטת מותג, בדקו כל שילוב: השתמשו בצבעי המותג כצבעים מוצקים בלבד, ועשו גרדיאנט רק בין גוונים סמוכים (למשל Israeli Blue → Israeli Blue Light) או דעיכה לנייטרל (cream / navy). צבע מוצק אחד עדיף על גרדיאנט מאולץ.

13. **בדקו את הטקסט שלכם עצמכם ב-bidi. גם בסקיל הזה.** סקיל שמזהיר על `<bdi>` חסר יפספס את ה-`<bdi>` שלו עצמו בתוך משפטים כמו "השתמשו ב-RTL" שאמור להיות "השתמשו ב-`<bdi>`RTL`</bdi>`". כשאתם כותבים טקסט, שקפים, או דוגמאות, סרקו ידנית כל מילה לטינית בתוך טקסט עברי ועטפו ב-`<bdi>`. מזהי קוד, שמות מותגים, גרסאות, סיומות קבצים — כולם צריכים בידוד. מי שכותב את הכלל לא פטור מהכלל.
