# השוואת עלויות ענן בישראל

## הוראות

### שלב 1: הבנת דרישות הענן של המשתמש

אסוף את המידע הבא לפני השוואת עלויות:

1. **סוג העומס**: אפליקציית ווב, backend של API, צינור נתונים, אימון ML, אתר סטטי, מסד נתונים
2. **היקף**: תעבורה צפויה (בקשות/חודש), אחסון נתונים (GB/TB), צרכי מחשוב (vCPU/RAM)
3. **דרישות ציות**: האם הנתונים חייבים להישאר בישראל? האם יש דרישות רגולטוריות (רשות הגנת הפרטיות, GDPR למשתמשים אירופיים)?
4. **תקציב**: תקציב חודשי בשקלים או דולרים, העדפה לתשלום לפי שימוש מול מחויבות
5. **מחסנית טכנולוגית**: שפה/פריימוורק, סוג מסד נתונים, העדפה לקונטיינרים או serverless
6. **מסלול צמיחה**: סטארטאפ (צמיחה מהירה), עסק קטן-בינוני (יציב), או ארגון (צפוי)
7. **קרדיטים ומבצעים קיימים**: שאל במפורש האם למשתמש יש קרדיטים פעילים, שכבה חינמית, מבצעים או תוכניות הנחה אצל ספק ענן כלשהו. זה כולל: הטבות שכבה חינמית (למשל AWS Free Tier עם מגבלות לפי שירות, GCP $300 ניסיון, Azure $200 ניסיון), קרדיטים מתוכניות סטארטאפ (AWS Activate, GCP for Startups, Microsoft Founders Hub), קרדיטים לסטודנטים (GitHub Student Pack), קרדיטים מהאקתונים או אירועים, קרדיטים מקרנות הון סיכון או מאיצים, או כל יתרה פרומוציונאלית אחרת. קרדיטים קיימים יכולים לשנות את ההשוואה לחלוטין וחובה לשקלל אותם בהמלצה.

### שלב 2: השוואת אזור AWS ישראל (il-central-1)

AWS השיקה את אזור ישראל (תל אביב) `il-central-1` באוגוסט 2023. פרטים עיקריים:

**שירותים זמינים ב-il-central-1:**
- EC2 (מחשוב), EBS (אחסון בלוקים), S3 (אחסון אובייקטים)
- RDS (מסדי נתונים מנוהלים: PostgreSQL, MySQL, Aurora)
- Lambda (serverless), ECS/EKS (קונטיינרים)
- ElastiCache (Redis/Memcached), DynamoDB
- CloudFront (CDN עם נקודת קצה בתל אביב), Route 53

**מדדי תמחור (il-central-1 מול eu-west-1 אירלנד):**
- מכונות EC2 נושאות פרמיה שטוחה של **כ-5%** מעל eu-west-1. נמדד באוגוסט 2026 על כל 324 סוגי המכונות המשותפים לשני האזורים דרך AWS Price List API: חציון 5.0%, טווח 4.3%-5.9%. הפרמיה אינה משתנה לפי משפחת מכונות. אל תמדלו טווח של 5%-15% ותיקחו את האמצע, זה מכפיל את הפער האמיתי
- אחסון S3 במחיר דומה
- **העברת נתונים החוצה אינה באותו תמחור גלובלי, וזהו פער העלות הגדול ביותר של האזור הישראלי.** יציאה לאינטרנט מ-il-central-1 עומדת על **0.110 דולר/GB** ל-10 הטרה-בייט הראשונים בחודש, מול **0.090 דולר/GB** מ-eu-west-1 ומ-us-east-1, כלומר פרמיה של 22%. במדרגות הגבוהות: 0.085 / 0.077 / 0.055 בתל אביב מול 0.085 / 0.070 / 0.050 באירלנד.
- **העברה בין אזורים היוצאת מתל אביב יקרה פי 4 מהתעריף האירופי, והיא אסימטרית.** יציאה מ-il-central-1 עולה **0.08 דולר/GB** לכל יעד שנבדק (אירלנד, פרנקפורט, וירג'יניה, קייפטאון, טוקיו). יציאה מ-eu-west-1 לאותם יעדים עולה 0.02 דולר/GB. תעבורה הנכנסת לתל אביב מאזור אחר מחויבת בתעריף הרגיל של אזור השליחה.
- שני הנתונים נקראו מ-AWS Price List API באוגוסט 2026, ממשק קריא-למכונה שניתן לבדוק מחדש, בניגוד לדפי התמחור השיווקיים.
- **זה משמעותי במיוחד לארכיטקטורה שהסקיל הזה ממליץ עליה בהמשך.** תכנון מפוצל ששומר נתונים באזור הישראלי ופונה לאזור אירופי לשירותים ש-il-central-1 חסר מייצר בדיוק את הרגל של 0.08 דולר/GB. ב-5 טרה-בייט לחודש הרגל הזו לבדה היא כ-400 דולר בחודש, שהשוואה שמניחה "היציאה זהה" תספור כאפס.
- מכונות RDS נושאות פרמיה חד-ספרתית דומה (לא נמדדה בנפרד)

**מתי להשתמש ב-il-central-1:**
- דרישות תושבות נתונים מחייבות אחסון ישראלי
- אפליקציות רגישות להשהיה המשרתות משתמשים ישראליים (1-3 מ"ש מקומי מול 40-60 מ"ש ל-eu-west-1)
- שירותים פיננסיים, בריאות או אפליקציות ממשלתיות
- ציות לתקנות רשות הגנת הפרטיות הישראלית

**מתי eu-west-1 עדיף:**
- אין דרישות תושבות נתונים ועלות היא השיקול העיקרי
- אפליקציות המשרתות משתמשים ישראליים ואירופיים כאחד
- זמינות שירותים רחבה יותר (שירותי AWS חדשים מושקים ב-eu-west-1 לפני il-central-1)

**כתובת תמחור:** `https://aws.amazon.com/ec2/pricing/on-demand/` (סנן לפי אזור: Israel)

### שלב 3: השוואת Google Cloud Platform (me-west1)

אזור `me-west1` של GCP ממוקם בתל אביב ונפתח ב-2022. (גרסה קודמת של הסקיל תיארכה את הזמינות הכללית לנובמבר 2022 וכינתה אותו האזור הראשון של GCP במזרח התיכון; לא ניתן היה לאמת אף אחת מהטענות, ו-me-central1 בדוחא מסבך את השנייה, אז שתיהן הוסרו.)

**שירותים זמינים ב-me-west1:**
- Compute Engine, Cloud Storage, Cloud SQL
- GKE (Kubernetes), Cloud Run (קונטיינרים serverless)
- Cloud Functions, Pub/Sub, BigQuery
- Memorystore (Redis), Cloud Spanner

**מדדי תמחור:**
- Compute Engine בדרך כלל 5%-10% זול יותר ממכונת EC2 מקבילה ב-il-central-1 של AWS
- תמחור Cloud Storage תחרותי עם S3
- הנחות שימוש מתמשך (sustained use) חלות אוטומטית (עד 30% עבור מכונות שרצות 100% מהחודש)
- הנחות שימוש מחויב: כ-37% (שנה) וכ-55% (3 שנים) לעומסים צפויים, אבל קראו קודם את טבלת המחויבויות בשלב 9: CUD מבוסס-משאב של GCP אינו ניתן לביטול וכבול לאזור ולמשפחת מכונות

**יתרונות GCP למפתחים ישראליים:**
- BigQuery זמין ב-me-west1 (חשוב לאנליטיקת נתונים עם מידע ישראלי)
- ל-Cloud Run יש שכבה חינמית; בדקו את מכסות הבקשות והחישוב החודשיות העדכניות בדף התמחור של Cloud Run במקום לצטט מספר מהזיכרון
- אחסון Firebase עם backend ב-me-west1 מספק אחסון full-stack בהשהיה נמוכה
- תוכנית GCP for Startups פעילה בישראל (ראה שלב 7)

**כתובת תמחור:** `https://cloud.google.com/compute/vm-instance-pricing` (סנן לפי אזור: me-west1)

### שלב 4: השוואת Microsoft Azure

Azure משרתת את ישראל בעיקר דרך האזורים הבאים:

**אזורים:**
- **Israel Central** (הושק בסוף 2023): אזור Azure מלא בישראל
- **West Europe** (הולנד): חלופה עם קטלוג שירותים רחב יותר

**שירותים זמינים ב-Israel Central:**
- Virtual Machines, Azure Blob Storage, Azure SQL
- AKS (Kubernetes), Azure Functions
- Azure Cosmos DB, Azure Cache for Redis

**מדדי תמחור:**
- מכונות Azure ב-Israel Central יקרות יותר ב-5%-12% בדרך כלל מ-West Europe
- Azure Blob Storage במחיר תחרותי עם S3 ו-Cloud Storage
- Azure מציעה תמחור הטבת היברידית: הבא רישיונות Windows/SQL Server שלך לחיסכון של עד 40%

**יתרונות Azure:**
- אינטגרציה חזקה עם אקוסיסטם Microsoft הארגוני (Active Directory, Office 365, Teams)
- שימו לב ש**Azure Government אינו רלוונטי כאן**: זהו ענן ריבוני אמריקאי ללקוחות ממשל פדרלי, מדינתי, מקומי ו-DoD בארה"ב, ולא משהו שרוכש ממשלתי ישראלי יכול לרכוש. מיקרוסופט מתחרה על עבודה במגזר הציבורי הישראלי דרך אזור Israel Central המסחרי וערוצי ממשל נפרדים
- תמחור Dev/Test: הנחות משמעותיות לסביבות שאינן ייצור
- Azure Reservations: מיקרוסופט מפרסמת עד 72% מול pay-as-you-go במחויבות לשנה או לשלוש שנים. ראו את טבלת המחויבויות בשלב 9 לתקרת הביטול ולשינוי ההחלפה מ-1 בפברואר 2027

**כתובת תמחור:** `https://azure.microsoft.com/en-us/pricing/calculator/`

### שלב 5: השוואת Oracle Cloud Infrastructure (il-jerusalem-1)

אזור ישראל המרכזי של Oracle, `il-jerusalem-1`, שוכן במרכז נתונים תת-קרקעי ממוגן מתחת לאזור התעשייה הר חוצבים בירושלים. (הפרטים שחוזרים בפרסומים, השקה ביולי 2021 ובניין בן 17 קומות מעליו, מקורם בסיקור עיתונאי שאינו נגיש כרגע לאחזור, אז התייחסו אליהם כמשוערים ואל תצטטו אותם.) זה היה אזור ה-hyperscaler הראשון בישראל (לפני GCP me-west1, AWS il-central-1 ו-Azure Israel Central) והוא ממוקם לעומסי עבודה הדורשים אבטחה וזמינות גבוהה.

**שירותים זמינים ב-il-jerusalem-1:**
- Compute (VM ו-bare-metal), Block Volumes, Object Storage
- Oracle Autonomous Database (המוצר הדגל של OCI), MySQL HeatWave, PostgreSQL
- Container Engine for Kubernetes (OKE), Functions (serverless)
- Oracle Fusion Cloud Applications

**עמדת תמחור:**
- Oracle מפרסמת מחירון גלובלי אחד. שירותי OCI מתומחרים זהה בין כל האזורים כולל il-jerusalem-1 (תמיד אמתו במחירון הרשמי לפני שמצטטים)
- Egress: 10 TB/חודש ראשונים החוצה כלולים בחינם בכל אזורי OCI. זו אחת ממדיניות ה-egress האגרסיביות יותר בין ה-hyperscalers
- מחירון: `https://www.oracle.com/il-en/cloud/price-list/`
- מחשבון עלויות: `https://www.oracle.com/il-en/cloud/costestimator.html`

**מתי לשקול OCI il-jerusalem-1:**
- עומסי עבודה סביב Oracle Database / Exadata בהם הרישוי כבר מטה את הכף ל-OCI
- פריסות עם דרישות אבטחה פיזית גבוהה או תשתית קריטית, בהן המיגון הפיזי של הבונקר התת-קרקעי הוא דרישה אמיתית
- עומסי egress צפויים וכבדים בהם 10 TB/חודש החינמיים זזים את המחט
- ממשלה ותעשייה מפוקחת שצריכות אזור ישראלי אבל מעדיפות ספק מחוץ לחוזה Project Nimbus של AWS ו-Google

**מגבלות:**
- אקוסיסטם צד-שלישי וקטלוג שירותים מנוהלים קטנים יותר מ-AWS/Azure/GCP
- פחות תוכניות קרדיטים לסטארטאפים ופחות שותפויות עם מאיצים ישראליים
- חלק משירותי OCI החדשים (במיוחד יכולות generative-AI) מושקים תחילה בארה"ב או באירופה

### שלב 5ב: הערכת ספקי ענן ישראליים

למקרי שימוש ספציפיים, ספקי ענן ישראליים עשויים להציע יתרונות:

**Kamatera (`https://www.kamatera.com`):**
- חברה ישראלית. דף התמחור שלה מציין מיקום ישראלי אחד, **תל אביב**; אם למשתמש נדרש אתר ישראלי ספציפי, אמתו את הפריסה הנוכחית מול Kamatera במקום להניח שיש כמה
- תמחור תחרותי: החל מכ-4 דולר/חודש ל-VPS בסיסי (1 vCPU, 1GB RAM). אמתו את המחיר העדכני בדף Kamatera לפני ציטוט
- מודל pay-as-you-go: תשלום רק על מה שמשתמשים, חיוב שעתי או חודשי, ללא חיובי תעבורה מפתיעים
- 30 יום ניסיון חינם
- מתאים ל: פרויקטים קטנים, סביבות פיתוח, אפליקציות לשוק הישראלי
- מגבלות: קטלוג שירותים קטן יותר מ-hyperscalers, ללא Kubernetes מנוהל
- חיוב בשקלים פורסם היסטורית. אם המשתמש דורש חשבונית שקלית מובטחת, אמתו ישירות מול מכירות Kamatera כי מדיניות מטבע החיוב השתנתה בין מפיצים אזוריים

**הערה:** HostIL (`hostil.co.il`) הוא ספק אחסון ישראלי שמופיע במדריכים שונים, אך לא ניתן היה לאמת באופן עצמאי את הסטטוס התפעולי הנוכחי שלו. בדקו את האתר ישירות לפני שמסתמכים עליו.

**Akamai / Linode**: ל-Akamai יש משרד בתל אביב אבל נכון למאי 2026 אין מרכז נתונים של Linode Connected Cloud בישראל. משתמשים ישראליים פונים בדרך כלל לאזורי Linode בפרנקפורט או אמסטרדם, מה שמוסיף 45-65 מ"ש השהיה. אל תמליצו על Linode כאופציה "ישראלית".

**DigitalOcean, Vultr, Hetzner, OVH**: אף אחד לא מפעיל מרכז נתונים בישראל. משתמשים ישראליים על הפלטפורמות האלה משתמשים בדרך כלל בפרנקפורט (Hetzner, DigitalOcean), שטרסבורג (OVH) או אמסטרדם, עם 45-65 מ"ש השהיה לתל אביב. Hetzner היא אופציית ה-EU הזולה ביותר לעומסי עבודה שאינם דורשים תושבות ישראלית, אבל היא כבר לא זולה כמו שהשוואות ישנות מרמזות: עדכון המחירים שלה מ-15 ביוני 2026 העלה את CX23 הבסיסי מ-3.99 ל-5.49 יורו/חודש נטו, וחלק מקווי CPX ו-CCX עלו הרבה יותר. צטטו 5.49 יורו/חודש כרצפה הנוכחית, לא את המספר סביב 4 יורו שמסתובב.

### שלב 6: השוואת תושבות נתונים וציות

כללי הגנת המידע והרגולציה הסקטוריאלית בישראל קובעים את הרשימה הקצרה לפני שהמחיר עושה זאת. הטיפול המלא, כולל טבלת התושבות לפי ספק ופרויקט נימבוס, נמצא בקובץ `references/compliance-he.md`.

הנקודות שמשנות המלצה:

- **תיקון 13 לחוק הגנת הפרטיות** בתוקף מ-14 באוגוסט 2025. שימו לב למה הוא עשה ומה לא: כללי ההעברה חוצת-הגבולות יושבים בתקנות משנת 2001 וקודמים לו; תיקון 13 הוא רפורמת האכיפה, ממונה הגנת הפרטיות והדיווח על אירועי אבטחה. אל תאמרו למשתמש שהארכיטקטורה שלו מלפני 2025 לא הייתה מפוקחת.
- **העברה חוצת-גבולות דורשת בסיס מתועד**, לא ברירת מחדל. אל תיפלו בשתיקה ל-eu-west-1 או ל-europe-west4 לשירות ישראלי שמחזיק מידע אישי. הרשות להגנת הפרטיות הידקה את התנאים המעשיים למסלול "אחריות בעל השליטה"; אתר הרשות אינו נגיש לסוכן, אז הפנו את המשתמש לבדוק את ההנחיה העדכנית.
- **גופים בפיקוח בנק ישראל**: האילוץ המחייב הוא תהליך פיקוחי ולא מיקום אחסון. הוראת ניהול בנקאי תקין 364 (בתוקף מ-18/05/2026, שהחליפה את 357, 361 ו-363) מסדירה ניהול סיכוני טכנולוגיית מידע, אבטחת מידע וסייבר. מה שנבחן הוא הערכת המיקור החוץ, מהותיות, תכנון יציאה והפיכות, זכויות ביקורת בחוזה ושרשרת קבלני המשנה. בחירת האזור נגזרת מזה, אז ערבו את הציות ואת המפקח לפני הכנת רשימה קצרה.
- **בריאות וממשל**: מידע של קופות חולים ובתי חולים ומכרזים ממשלתיים נושאים לרוב דרישות לוקליות ישראליות, אך הן מוטלות בחוזרים ובסעיפי מכרז ספציפיים. בקשו את הסעיף עצמו לפני שאתם מתכננים לפיו במקום להניח את הפרשנות המחמירה ביותר.
- **תושבות אינה ריבונות.** כל אזור ישראלי שומר את המידע בישראל בעוד המפעיל נשאר כפוף לתחום השיפוט של מדינת האם שלו.
- **PCI DSS חל בנפרד** על נתוני כרטיסי אשראי.

### שלב 6ב: פרויקט נימבוס (ענן ריבוני ממשלתי)

פרויקט נימבוס הוא חוזה הענן הממשלתי הישראלי בשווי 1.2 מיליארד דולר שנחתם עם AWS ו-Google ב-2021. זה **לא שירות ציבורי לכל לקוח**. זהו שוכר ריבוני נגיש למשרדי ממשלה, גופי ביטחון ושותפים מאושרים. אל תמליצו עליו לסטארטאפים כלליים או ללקוחות מסחריים.

**מתי נימבוס רלוונטי:**
- המשתמש הוא משרד ממשלתי, ספק מגזר ביטחוני, או קבלן המבצע עומס מסווג שחייב לרוץ בתוך שוכר נימבוס
- המשתמש מעריך עם איזה hyperscaler להתיישר לקראת מכרזים ממשלתיים עתידיים (ל-AWS ול-Google יש את תשתית נימבוס. Azure ו-Oracle מתחרים בערוצי ממשל נפרדים)

**מה כדאי לדעת:**
- נימבוס משתמש בתשתית ייעודית בתוך ישראל תחת תנאי ריבונות חוזיים השונים מאזורי AWS/GCP הציבוריים
- דיווחים פומביים (סוף 2025 עד תחילת 2026) מתארים "מנגנון קריצה" המחייב את AWS ו-Google לעדכן את משרד האוצר הישראלי בקודים מוצפנים אם בית משפט זר ידרוש מידע מנימבוס. זה לא בקרה טכנית, זה תנאי חוזי, והוא ממשיך לעורר בחינה ביקורתית בקרב חוקרים ועובדים בשתי החברות
- ישראל אינה מפעילה כיום ענן ריבוני מלא (מחסנית בשליטה ישראלית עם עיבוד AI ריבוני). נימבוס הוא הסדר "המידע נשאר בישראל" על תשתית AWS/Google ולא מחסנית בשליטה ריבונית

### שלב 7: שקלול קרדיטים, שכבות חינמיות ומבצעים

קרדיטים ומבצעים יכולים לשנות את ההשוואה מקצה לקצה. ספק שיקר ב-20% במחירון עשוי להיות הזול ביותר ל-6-12 חודשים אם למשתמש יש שם קרדיטים. תמיד בדקו מה כבר יש למשתמש לפני שממליצים.

#### 7א ו-7ב: שכבות חינמיות, ניסיונות ותוכניות קרדיטים לסטארטאפים

קרדיטי הניסיון לכל ספק, קטלוגי השירותים החינמיים, וכל תוכניות הקרדיטים לסטארטאפים (AWS Activate,
Google for Startups, Microsoft Founders Hub, מענקי רשות החדשנות ותוכנית תל"ם ל-B200) נמצאים בקובץ
`references/pricing-and-credits-he.md`, עם הסכומים כפי שנקראו ב-19 באוגוסט 2026.

קראו את הקובץ לפני ציטוט מספר כלשהו. שלושה דברים שם מנוגדים מספיק לאינטואיציה כדי לומר אותם כאן:

- **השכבה החינמית של AWS כבר אינה מגבלות לפי שירות ל-12 חודשים.** זהו קרדיט חד-פעמי של עד $200,
  והחשבון נסגר מעצמו אחרי 6 חודשים או כשהקרדיט נגמר.
- **תקרות הקרדיטים לסטארטאפים עלו מהותית ב-2026**, ורוב הסיכומים המשניים עדיין מצטטים את הישנות.
- **תקרה היא תקרה.** צטטו אותה ככזו, לא כסכום צפוי.

#### 7ג. מקורות קרדיטים נוספים

- **תוכניות לסטודנטים**: GitHub Student Developer Pack כולל קרדיטים מ-AWS, GCP, Azure ו-DigitalOcean
- **קרדיטים מהאקתונים ואירועים**: AWS, GCP ו-Azure מחלקים באופן קבוע $500-$2,000 בקרדיטים באירועי מפתחים והאקתונים בישראל (בדקו ב-Meetup.com ו-Eventbrite לאירועי טק ישראליים)
- **קרדיטים מקרנות הון סיכון ומאיצים**: מאיצים ישראליים רבים (8200 EISP, MassChallenge Israel, Techstars) כוללים קרדיטי ענן כחלק מהתוכניות שלהם
- **תוכניות שותפים**: הסכמי שותפות טכנולוגית עם AWS, GCP או Azure עשויים לכלול הקצאות קרדיטים

#### 7ד. שימוש בקרדיטים קיימים בהשוואה

אם המשתמש מדווח על קרדיטים קיימים אצל ספק כלשהו, יש להתאים את ההשוואה:

1. **חשב את משך הקרדיטים**: לכמה חודשים יספיקו הקרדיטים ברמת השימוש המוערכת?
2. **השווה בין ספקים**: גם אם ספק A נתן למשתמש קרדיטים, בדוק אם לספק B או C יש הצעות דומות או טובות יותר שהמשתמש אולי לא יודע עליהן
3. **הצג שני תרחישים**: הצג עלויות "עם הקרדיטים הנוכחיים" וגם "אחרי שהקרדיטים נגמרים" כדי שהמשתמש יוכל לתכנן קדימה
4. **הזהר מנעילת ספק**: קרדיטים שפגים עלולים לדחוף משתמש לספק שעולה יותר בטווח הארוך. יש לסמן סיכון זה.

### שלב 8: ביצוע מדידת השהיה

זמני הלוך-ושוב משוערים מתל אביב: **1-3 מ"ש** לשלושת אזורי תל אביב (AWS il-central-1, GCP me-west1, Azure Israel Central), **3-6 מ"ש** ל-Oracle il-jerusalem-1, **45-65 מ"ש** למערב אירופה, ו-**130-160 מ"ש** לחוף המזרחי של ארה"ב. הטבלה המלאה נמצאת בקובץ `references/cost-mechanics.md`, עם הסתייגות ש**לאף אחד מהמספרים האלה אין מקור מפורסם מטעם הספק**, אז השתמשו בהם לרשימה קצרה ומדדו מהרשת של המשתמש עצמו אם ההחלטה תלויה בהשהיה.

לאפליקציות פונות-משתמש שמשרתות משתמשים ישראליים, פחות מ-5 מ"ש מאזור מקומי מורגש טוב יותר מ-50 מ"ש ומעלה, וההפרש מוכפל במספר הקריאות הסדרתיות של ה-API. לעיבוד אצווה ולצינורות נתונים ההשהיה פחות משנה; מטבו לעלות. CDN ממתן השהיה לנכסים סטטיים ללא תלות באזור המקור.

### שלב 9: חישוב עלות בעלות כוללת

**תוכניות הנחה במחויבות (תמיד אמת מול דפי התמחור הרשמיים, מאחר שהתנאים משתנים):**
- **AWS Savings Plans** (Compute ו-EC2 Instance Savings Plans): AWS מפרסמת **עד 72%** הנחה ממחיר on-demand במחויבות לשנה או לשלוש שנים. גמישות יותר מ-Reserved Instances הקלאסיים, מאחר שהן חלות על מספר משפחות מכונות ואזורים (במקרה של Compute Savings Plans). RIs עדיין זמינים ל-RDS, ElastiCache, Redshift ו-OpenSearch.
- **GCP Committed Use Discounts (CUDs)**: CUDs מבוססי הוצאה ו-CUDs מבוססי משאבים ל-Compute Engine ולשירותים נוספים, וגם **Flexible CUDs** שחלים על מספר משפחות מכונות ואזורים. הנחות Sustained Use ממשיכות לחול אוטומטית על שימוש on-demand.
- **Azure Reservations** (שנה / שלוש שנים) ל-VMs, SQL DB, Cosmos DB, Cache for Redis וכו', ובנוסף **Azure Savings Plan for Compute** שגמיש יותר על פני אזורים וסדרות מכונות. מיקרוסופט מפרסמת עד 72% מול pay-as-you-go.

**הנחות התחייבות** (AWS Savings Plans עד 72%, GCP CUDs, Azure Reservations עד 72%) מכוסות יחד עם המחויבויות, תנאי הביטול ושינוי ההחלפה של Azure מ-1 בפברואר 2027 בקובץ `references/cost-mechanics.md`. קראו אותו לפני שאתם ממליצים על תקופה: התחייבו לרצפת 90 הימים האחרונים ולא לממוצע, אל תתחייבו באמצע הגירה, ואל תתחייבו בזמן שקרדיטים עדיין מכסים את החשבון.

בנה השוואת עלויות מקיפה הכוללת:

1. **עלויות מחשוב**: תמחור on-demand מול reserved/committed מול savings plan מול spot/preemptible
2. **עלויות אחסון**: אחסון אובייקטים + אחסון בלוקים + אחסון מסד נתונים
3. **עלויות רשת**: העברת נתונים החוצה (egress), העברה בין-אזורית, עלויות CDN
4. **עלויות שירותים מנוהלים**: מסדי נתונים, מטמונים, תורי הודעות, ניטור
5. **עלויות תמיכה**: AWS שינתה שמות ומבנה. אין יותר שכבת Developer או Business; שלוש התוכניות בתשלום הן **Business Support+** (מינימום 29 דולר/חודש לחשבון), **Enterprise Support** (5,000 דולר/חודש) ו-**Unified Operations** (50,000 דולר/חודש), כל אחת מתומחרת כגבוה מבין המינימום לבין אחוז מהחיוב החודשי. ציטוט של "Developer 29 דולר / Business 100 דולר" אינו מעודכן
6. **השפעת מטבע**: תנודות תמחור בדולר עבור חברות עם תקציב בשקלים. AWS, GCP ו-Oracle מחייבים בדולרים; Azure מציעה אפשרויות חיוב בשקלים דרך הסכמי enterprise ישראליים. השקל המשיך להתחזק: השער היציג של בנק ישראל עמד על **2.985 ב-19 באוגוסט 2026**, לעומת כ-3.70 ב-2024, אחרי מסחר בטווח של סוף שנות ה-2.9 עד תחילת ה-3.0 לאורך אוגוסט. תקציב ענן שקלי שהוגדר לפי שער 2024 קונה היום בערך 20%-25% יותר דולרים ממה שתוכנן. לתקצוב, השתמשו בשער היציג של בנק ישראל ולא במספר שמצוטט כאן, ותקצבו מחדש רבעונית לפי ממוצע נע של שלושה חודשים.
7. **עלויות נסתרות**: חיובי NAT Gateway (AWS), שכבת רשת פרימיום (GCP), רישום דיאגנוסטי (Azure)

### שלב 9ב: תמחור עומסי GPU ו-AI

תמחור GPU הוא ציר עלות נפרד, והוא הנתון שזז הכי מהר בסקיל הזה. התעריפים הנוכחיים לשעת GPU אצל
ה-hyperscalers ואצל ספקי הענן הייעודיים, תעריפי H200 ו-B200, ומסלול תל"ם של רשות החדשנות, כולם
נמצאים בקובץ `references/pricing-and-credits-he.md`.

צורת השוק, שמשתנה לאט יותר מהמספרים:

- ספקי ענן ייעודיים (Lambda, RunPod, Vast.ai) זולים ממחירון ה-hyperscalers, אבל הפער הצטמצם במהלך
  2026 ולאף אחד מהם אין אזור בישראל, אז צפו ל-80-150 מ"ש מתל אביב.
- זמינות GPU באזורים הישראליים דלילה; בדקו את קטלוג המאיצים של האזור לפני שאתם מבטיחים משפחת מכונות
  ספציפית ב-il-central-1 או ב-me-west1.
- לסטארטאפ AI ישראלי שמבצע אימון אמיתי ולא רק הסקה, שווה לרדוף אחרי הקצאת תל"ם לפני התחייבות להזמנת
  GPU אצל hyperscaler, גם במחיר וגם כי נתוני האימון נשארים בישראל.

**מסגרת המלצה ל-GPU:**
- **הסקה, רגישות להשהיה, משתמשים ישראליים**: מכונת GPU באזור ישראלי אם המשפחה זמינה, אחרת קבלו את הקפיצה לאירופה
- **אימון, ללא דרישת תושבות, רגישות לתקציב**: ספקים ייעודיים באירופה או בארה"ב
- **אימון, מו"פ AI ישראלי**: הגישו לתל"ם קודם, ורדו לספקים ייעודיים כגיבוי
- **הסקה בקצב קבוע בקנה מידה**: הנחות התחייבות סוגרות את רוב הפער מול ספקים ייעודיים מעל ניצולת של כ-60%

### שלב 10: הצגת המלצות

מבנה ההמלצה הסופית:

1. **טבלת סיכום**: השוואת עלויות זה לצד זה לדרישות הספציפיות של המשתמש
2. **השוואה מותאמת לקרדיטים**: אם למשתמש יש קרדיטים אצל ספק כלשהו, הצג שורה או טבלה נפרדת עם העלות החודשית בפועל אחרי ניצול הקרדיטים. כמו כן, ציין באופן יזום מבצעים דומים אצל ספקים אחרים שהמשתמש אולי לא מודע אליהם.
3. **המלצה ראשית**: הספק הטוב ביותר למקרה השימוש של המשתמש עם הצדקה. אם קרדיטים מטים את הכף בצורה משמעותית לטובת ספק מסוים בטווח הקצר, ציין זאת בבירור אבל גם המלץ על הבחירה הטובה ביותר לטווח הארוך אחרי שהקרדיטים נגמרים.
4. **המלצה חלופית**: האפשרות השנייה בטובה עם הסבר על הפשרות
5. **טיפים לאופטימיזציית עלויות**: פעולות ספציפיות להפחתת עלויות (reserved instances, שימוש ב-spot, התאמת גודל)
6. **שיקולי מיגרציה**: אם המשתמש כבר על ספק, הער את מאמץ המיגרציה וחששות נעילה
7. **צעדים הבאים**: קישורים לשכבה חינמית / הצעות ניסיון להערכה מעשית

## דוגמאות

### דוגמה 1: סטארטאפ מעריך ענן למוצר SaaS חדש

המשתמש אומר: "אנחנו סטארטאפ ישראלי בשלב seed שבונה מוצר SaaS עסקי. אנחנו מצפים ל-1,000 משתמשים בשנה הראשונה, בעיקר חברות ישראליות. המחסנית שלנו היא Node.js + PostgreSQL + Redis. התקציב כ-5,000 שקלים/חודש."

פעולות:
1. הער צרכי תשתית: 2 שרתי אפליקציה (2 vCPU, 4GB כל אחד), PostgreSQL מנוהל (מקביל ל-db.t3.medium), Redis מנוהל (מקביל ל-cache.t3.small), 50GB אחסון S3
2. חשב עלויות ב-AWS il-central-1, GCP me-west1 ו-Azure Israel Central
3. בדוק זמינות קרדיטים לסטארטאפים: המלץ להגיש ל-AWS Activate, GCP for Startups ו-Microsoft Founders Hub
4. שקלל תושבות נתונים: SaaS עסקי לחברות ישראליות עשוי ליהנות מאחסון מקומי לשיחות מכירה
5. שקול Kamatera כאפשרות חסכונית לסביבות פיתוח/staging

תוצאה: המלץ על GCP me-west1 כעיקרי (הנחות שימוש מתמשך + תמחור תחרותי + Cloud Run למיקרו-שירותים) עם AWS il-central-1 כחלופה. הדגש שקרדיטים לסטארטאפים משני הספקים יכולים לכסות 12-18 חודשים של אחסון. הצע Kamatera לסביבת staging בכ-100 שקלים/חודש. עלות ייצור משוערת: 1,500-2,500 שקלים/חודש לפני קרדיטים.

### דוגמה 2: ארגון מהגר מתשתית מקומית לענן

המשתמש אומר: "אנחנו חברת שירותים פיננסיים בתל אביב עם 50 שרתים מקומיים. אנחנו צריכים לעבור לענן עם תושבות נתונים ישראלית. העומסים שלנו כוללים עיבוד עסקאות, מסדי נתוני דיווח ופורטל לקוחות."

פעולות:
1. מפה תשתית נוכחית למקבילות ענן (50 שרתים עם מפרטים שונים)
2. זהה דרישות ציות: תקנות בנק ישראל, תושבות נתונים PPA, PCI DSS לעיבוד תשלומים
3. השווה AWS il-central-1 מול Azure Israel Central (לשניהם ציות שירותים פיננסיים)
4. חשב תמחור reserved instances לעומסים צפויים (אפשרויות שנה ו-3 שנים)
5. כלול עלויות מיגרציה: כלי AWS Migration Hub או Azure Migrate, הקמת רשת, בדיקות

תוצאה: המלץ על Azure Israel Central כעיקרי בזכות הטבות רישוי היברידי (הבא רישיונות Windows/SQL Server קיימים) ועמדת ציות חזקה לשירותים פיננסיים. AWS il-central-1 כחלופה אם לצוות יש יותר מומחיות AWS. עלות חודשית משוערת: 15,000-25,000 דולר/חודש עם reserved instances ל-3 שנים. אל תציעו את Azure Government למכרזים ממשלתיים ישראליים עתידיים: זהו ענן ריבוני אמריקאי ללקוחות ממשל בארה"ב. לעבודה במגזר הציבורי הישראלי השיחה הרלוונטית היא אזור Israel Central המסחרי ודרישות המכרז.

### דוגמה 3: מפתח בוחר אחסון לפרויקט צדדי

המשתמש אומר: "אני בונה פרויקט אישי, כלי NLP לעברית. אני צריך שרת קטן עם גישת GPU להסקה, ומסד נתונים. תקציב מינימלי."

פעולות:
1. זהה צרכי GPU: הסקה בלבד דורשת GPU קטן יותר (T4 או מקביל)
2. השווה תמחור GPU: AWS g4dn.xlarge, GCP n1-standard-4 + T4, Azure NC4as_T4_v3
3. שקול מכונות spot/preemptible לחיסכון של 60%-80% על מחשוב GPU
4. בדוק אם מכונות GPU זמינות באזורים ישראליים (זמינות מוגבלת)
5. הער חלופות: מכונות GPU של Kamatera, או Lambda Labs / RunPod להסקה בלבד

תוצאה: לפרויקט צד של הסקה בלבד, הדרך הזולה ב-2026 היא ספק GPU ייעודי (Lambda Labs, RunPod או Vast.ai) שמריץ מכונת L4 או T4 בכ-$0.40-$1.00/שעה, בשילוב עם PostgreSQL מנוהל קטן בכל מקום. GCP me-west1 Cloud SQL micro, AWS RDS db.t4g.micro ב-il-central-1, או אפילו VM של Kamatera למסד נתונים. אם הפרויקט צריך תושבות ישראלית או השהיה מתחת ל-5 מ"ש, השתמשו ב-GCP me-west1 עם מכונת GPU preemptible/spot ועם Cloud SQL micro. עלות משוערת במסלול ספק ייעודי: כ-150-350 שקלים/חודש בשער סביב 3.0 ILS/USD (בדקו את השער היציג הנוכחי של בנק ישראל לפני ציטוט). לסטארטאפ AI ישראלי עם עומסי אימון אמיתיים (לא רק הסקה), המליצו להגיש בקשה לתוכנית תל"ם של רשות החדשנות לגישה מסובסדת ל-Nvidia B200 דרך Nebius לפני שמתחייבים להזמנת GPU ב-hyperscaler. לעלות מינימלית עוד יותר, הציעו הרצת הסקה על CPU עם מודלים מקוונטזים אם סובלנות ההשהיה מאפשרת.

## מלכודות נפוצות

- **לכל מחיר מחירון בסקיל הזה יש חיי מדף של שבועות, וגם תוכניות הקרדיטים זזות.** בין הסקירה הקודמת לנוכחית AWS החליפה את כל השכבה החינמית שלה, שינתה שמות לשלוש תוכניות התמיכה, הכפילה את Activate Portfolio, וגוגל שינתה את מבנה תוכנית הסטארטאפים; Hetzner העלתה מחירים ו-Lambda העלתה את תעריף ה-H100 בכ-60%. התייחסו לכל מספר כאן כעוגן פתיחה שצריך אימות מחדש בדף של הספק, ואמרו למשתמש באיזה תאריך בדקתם. סוכן שמצטט את המספרים האלה כעדכניים כמה חודשים אחר כך הוא מצב הכשל הסביר ביותר של הסקיל הזה.
- **עיוורון קרדיטים**: כשמשתמש מציין שיש לו קרדיטים או מבצעים אצל ספק מסוים, סוכנים נוטים להמליץ מיד על אותו ספק בלי לבדוק אם ספקים אחרים מציעים עסקאות דומות או טובות יותר. תמיד יש להשוות תוכניות קרדיטים בין כל הספקים לפני שממליצים. למשל, משתמש עם $100 קרדיטים ב-AWS אולי לא יודע ש-GCP מציעה $300 בקרדיטי ניסיון, ש-Azure Founders Hub מציע עד $150,000 לסטארטאפים מגובי VC, או שתוכנית תל"ם של רשות החדשנות מציעה גישה מסובסדת ל-B200 לאימון AI.
- **דייקו את רשימת האזורים.** בישראל יש ארבעה אזורי hyperscaler: AWS il-central-1, GCP me-west1, Azure Israel Central ו-Oracle il-jerusalem-1. אל תאמרו למשתמש של-Oracle אין אזור ישראלי, ואל תציעו את AWS me-south-1 (בחריין) כ"גיבוי הקרוב ביותר"; הוא הפסיק להיות כזה כשנפתח il-central-1. ל-Akamai/Linode יש משרד בתל אביב אבל אין מרכז נתונים ישראלי, אז פרנקפורט היא הגיבוי הרגיל שם. שימו לב גם שתמחור il-central-1 שונה מ-eu-west-1, ולכן מחירוני מחירון גלובליים מתמחרים אותו בחסר.
- **מע"מ ישראלי על חשבוניות ענן: דייקו את המנגנון, ואמרו איזה מספר אתם מצטטים.** כשהספק מחייב דרך ישות רשומה בישראל, החשבונית נושאת 18% מע"מ גם ללקוח עסקי; עוסק מורשה מקזז אותו כמס תשומות ולא מחויב נטו מלכתחילה. ההבחנה משנה שני מספרים שונים: תזרים (החשבונית שעסק באמת משלם גבוהה ב-18% מהצעה ללא מע"מ) ועלות אמיתית (עסק שמקזז במלואו לא נושא בו, וגוף שאינו מקזז במלואו נושא בכולו). תמיד ציינו אם מספר הוא כולל או לא כולל מע"מ. **אמתו מול כל ספק בנפרד** אם ישות החיוב רשומה בישראל לפני הכללה, והפנו כל מי שמצב הקיזוז שלו אינו פשוט, ומוסדות כספיים בפרט, לרואה החשבון שלו ולא לתשובה כאן.
- **העברה חוצת-גבולות דורשת בסיס מתועד תחת תיקון 13 לחוק הגנת הפרטיות** (בתוקף מ-14 באוגוסט 2025). אל תעברו בשתיקה לברירת מחדל של eu-west-1 או europe-west4 ל-SaaS ישראלי שמחזיק מידע אישי. הבחירה צריכה להתאים לאחת מחריגות סעיף 2 (רשימת מדינות מאושרות, מסלול אחריות בעל השליטה תחת הנחיית הרשות מאפריל 2026 וכו'). דרישות אחסון מידע בישראל למכרזים ממשלתיים עשויות לחייב אחסון בתוך ישראל. סוכנים עלולים להמליץ על אזורים בינלאומיים זולים יותר שמפרים דרישות אלה.
- **דריפט מטבע**: USD/ILS ירד מכ-3.70 ב-2024 ל-**2.985 ב-19 באוגוסט 2026** (שער יציג של בנק ישראל). תקציב שקלי שהוגדר בשער הישן נדיב מדי בכ-20%-25% במונחי דולרים. כווננו את התקציב לפי השער היציג הנוכחי של בנק ישראל במקום למחזר המרות ישנות, כולל כל מספר שמצוטט בסקיל הזה.
- **פרויקט נימבוס הוא לא אופציה לסטארטאפים.** אל תמליצו על נימבוס ללקוחות מסחריים. זה חוזה ענן ריבוני ממשלתי על AWS ו-Google, לא מוצר ענן ציבורי.
- **קיבולת spot באזור קטן דלילה ותנודתית יותר מאשר ב-eu-west-1**, פשוט כי יש פחות אזורי זמינות ופחות צי פנוי, אז בנו נפילה-לאחור מודעת-קיבולת במקום להניח ש-spot תמיד שם. (גרסה קודמת של הסקיל ייחסה תנודות spot באזור ישראל לביקוש בשבת ובחגים. המנגנון הזה אינו מבוסס על מקור, ותמחור spot ב-AWS אינו מבוסס מכרז ביקוש מאז 2017, אז אל תציעו אותו למשתמש כאבחנה.)

## פתרון בעיות

### שגיאה: "שירות לא זמין באזור הישראלי"

סיבה: לא כל שירותי הענן זמינים בכל אזור. אזורים ישראליים (il-central-1, me-west1, Israel Central) הושקו לאחרונה ועשויים לחסר שירותים חדשים או מתמחים.

פתרון:
1. בדוק את דף זמינות השירותים האזורי של הספק:
   - AWS: `https://aws.amazon.com/about-aws/global-infrastructure/regional-product-services/`
   - GCP: `https://cloud.google.com/about/locations`
   - Azure: `https://azure.microsoft.com/en-us/explore/global-infrastructure/products-by-region/`
2. השתמש בארכיטקטורת רב-אזורית: שמור נתונים באזור הישראלי, הרץ שירותים לא זמינים באזור האירופי הקרוב ביותר
3. לשירותי serverless (Lambda, Cloud Functions), בדוק אם אפשר להפעילם בין-אזורית עם השהיה מקובלת
4. צור קשר עם הצוות הישראלי של הספק למפת דרכים של זמינות שירותים

### שגיאה: "עלויות גבוהות משמעותית מהאומדן"

סיבה: גורמי עלות בלתי צפויים נפוצים כוללים חיובי העברת נתונים, עמלות NAT Gateway (AWS), רשת פרימיום (GCP) ורישום דיאגנוסטי (Azure).

פתרון:
1. הפעל התראות עלות ותקציבים במסוף החיוב של ספק הענן
2. סקור את פירוט החיוב לפי שירות וזהה את מניעי העלות המובילים
3. גורמים נפוצים ותיקונים:
   - **NAT Gateway (AWS)**: כ-0.045 דולר/GB מעובד, אבל התעריף תלוי אזור וזהו המספר של US East, אז בדקו את הדף של il-central-1 לפני שאתם מצטטים אותו לפריסה ישראלית. שקלו VPC endpoints עבור S3/DynamoDB
   - **העברת נתונים**: חיובי egress מצטברים. השתמש ב-CloudFront/CDN לנכסים סטטיים, דחוס תגובות API
   - **משאבים לא פעילים**: בדוק מכונות רצות, אמצעי EBS לא מחוברים, כתובות Elastic IP שאינן בשימוש
   - **מסדי נתונים בגודל עודף**: מכונות RDS/Cloud SQL לעיתים רצות בניצולת 10%-20%. התאם גודל או השתמש בגרסאות serverless
4. השתמש בכלי FinOps: AWS Cost Explorer, GCP Recommender, Azure Advisor להצעות אופטימיזציה

### שגיאה: "חיוב בשקלים לא זמין"

סיבה: hyperscalers מרכזיים (AWS, GCP) מחייבים בדולרים. תנודות מטבע מוסיפות אי-ודאות תקציבית לחברות עם תקציב בשקלים.

פתרון:
1. Azure מציעה כמה אפשרויות חיוב בשקלים להסכמי enterprise ישראליים. צור קשר עם מכירות Microsoft ישראל.
2. Kamatera מחייבת באופן מקורי בשקלים
3. לספקים שמחייבים בדולרים, השתמש באסטרטגיות אלה:
   - הגדר תקציבים עם חיץ מטבעי של 10%
   - רכוש reserved instances בתקופות שער חליפין נוח
   - השתמש בחשבונות מט"ח עסקיים כדי להפחית עמלות המרה
   - שקול חוזים עתידיים עם הבנק שלך עבור הוצאות מחויבות גדולות
4. עקוב אחר שער חליפין דולר/שקל והתאם תקציבים כל רבעון
