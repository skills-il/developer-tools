# חיבורי Zapier לישראל

## הוראות

### שלב 1: בחירת דפוס ה-Zap המתאים

התאם את הצורך העסקי לארכיטקטורת Zap הנכונה. השתמש בטבלה הבאה כדי לקבוע איזה טריגר, שרשרת פעולות ואפליקציות ישראליות מעורבים.

| צורך עסקי | טריגר Zap | שרשרת פעולות | אפליקציות ישראליות |
|-----------|-----------|-------------|-------------------|
| קבלה אוטומטית אחרי תשלום | Webhook של קארדקום/טרנזילה | ניתוח תשלום -> יצירת מסמך בחשבונית ירוקה -> מייל ללקוח | קארדקום, חשבונית ירוקה |
| מעקב ליד בוואטסאפ | הגשת טופס (Typeform, Google Forms) | חילוץ שם בעברית -> עיצוב ברכה -> שליחת וואטסאפ דרך Twilio | וואטסאפ (Twilio), ספק טפסים |
| סנכרון חשבונית לניהול חשבונות | מסמך חדש בחשבונית ירוקה | מיפוי שדות -> יצירת רשומה בכלי הנהלת חשבונות -> תיוג תקופת מע"מ | חשבונית ירוקה, כלי הנהלת חשבונות |
| תזכורת תשלום (לעצמאים) | טריגר מתוזמן (דו-חודשי) | שליפת חשבוניות שלא שולמו -> סינון חובות -> שליחת תזכורת בעברית | חשבונית ירוקה, ספק מייל/SMS |
| עיבוד הזמנות e-commerce | הזמנה חדשה ב-WooCommerce/Shopify | יצירת חשבונית בחשבונית ירוקה -> אישור וואטסאפ -> עדכון בורד Monday.com | חשבונית ירוקה, Monday.com |
| סיווג הוצאות | מייל (קבלה מצורפת) | ניתוח קבלה -> סיווג לפי סוג ניכוי מס -> רישום בגיליון | Gmail, Google Sheets |

**בחירה בין Zap חד-שלבי לרב-שלבי:**
- Zap חד-שלבי (חינמי): טריגר ישירות לפעולה, למשל "תשלום חדש בקארדקום -> שורה חדשה ב-Google Sheets"
- Zap רב-שלבי (בתשלום): שרשור פעולות עם לוגיקה, למשל "תשלום חדש -> יצירת חשבונית -> וואטסאפ -> עדכון CRM"
- השתמש ב-Paths (הסתעפות) כשה-Zap צריך לטפל בתרחישים שונים, למשל "אם התשלום מעל 5,000 ש"ח, דרוש אישור מנהל"

### שלב 2: חיבור אפליקציות ישראליות ל-Zapier

אפליקציות ישראליות מתחברות ל-Zapier בשלוש דרכים. בחר לפי מה שהאפליקציה תומכת.

| אפליקציה | שיטת חיבור | סוג אימות | הערות |
|----------|-----------|----------|-------|
| חשבונית ירוקה (Green Invoice) | Webhooks by Zapier | מפתח API + Webhook | אין אפליקציה מובנית של Green Invoice בספריית Zapier. יש להתחבר דרך webhooks: שימוש בהתראות webhook של חשבונית ירוקה כטריגרים וב-REST API שלהם דרך Webhooks by Zapier לפעולות. יש ליצור מפתח API מהגדרות > אינטגרציית API בדשבורד. |
| קארדקום (Cardcom) | Webhooks by Zapier | כתובת Webhook | קארדקום שולח POST ל-Zapier על אירועי תשלום. הגדרה בהגדרות מסוף > התראות. |
| טרנזילה (Tranzila) | Webhooks by Zapier | כתובת Webhook | דומה לקארדקום. הגדרת כתובת התראה בפאנל הסוחר. |
| Monday.com | אינטגרציה מובנית ב-Zapier | OAuth | תמיכה מלאה. אפליקציה גלובלית עם אימוץ חזק בישראל. |
| ריווחית (Rivhit) | Webhooks by Zapier | מפתח API ב-header | אין אינטגרציה מובנית. יש להשתמש ב-webhook + קריאות API מותאמות. |
| Priority ERP | Webhooks by Zapier | Basic auth | שימוש ב-REST API של Priority דרך פעולות webhook. |
| ספקי SMS (019, InforUMobile) | Webhooks by Zapier | מפתח API | שליחת SMS דרך פעולת HTTP POST עם API של הספק. |

**הגדרת מפתח API של חשבונית ירוקה:**
1. התחבר לדשבורד של חשבונית ירוקה
2. נווט להגדרות > אינטגרציית API
3. צור מפתח API חדש
4. ב-Zapier, השתמש ב-"Webhooks by Zapier" כדי להתחבר דרך REST API של חשבונית ירוקה עם מפתח ה-API בכותרת Authorization

**הגדרת חיבור מבוסס Webhook (קארדקום, טרנזילה):**
1. ב-Zapier, צור Zap חדש עם "Webhooks by Zapier" כטריגר
2. בחר "Catch Hook" כאירוע טריגר
3. העתק את כתובת ה-webhook שנוצרה
4. בדשבורד של מעבד התשלומים, הדבק את הכתובת בשדה כתובת התראה/callback
5. בצע תשלום ניסיון כדי לשלוח נתוני דוגמה ל-Zapier
6. מפה את שדות ה-webhook בשלבי Zap הבאים

### שלב 3: טיפול בטקסט עברי בשלבי Zap

טקסט עברי דורש טיפול מיוחד ב-Zapier כדי למנוע בעיות תצוגה וקידוד.

**שלבי Formatter לעברית:**
- השתמש ב-"Formatter by Zapier > Text > Trim Whitespace" כדי לנקות קלט עברי שעלול להכיל סמני כיוון בלתי נראים (RTL/LTR markers, תווים U+200F ו-U+200E)
- עיצוב שמות: שמות בעברית הם "פרטי משפחה" (ללא שם אמצעי). השתמש ב-"Formatter > Text > Titlecase" רק לשמות באנגלית. לעברית, העבר כמות שהוא
- בעת שרשור טקסט עברי ואנגלי (למשל "Order #12345 - הזמנה חדשה"), מקם את החלק האנגלי קודם, ואז עברית. Zapier מציג טקסט דו-כיווני ב-LTR כברירת מחדל

**תבניות אימייל בטוחות ל-RTL:**
בשליחת אימיילים ב-HTML דרך Zapier, עטוף תוכן עברי עם כיוון מפורש:

```html
<div dir="rtl" style="text-align: right; font-family: Arial, sans-serif;">
  <p>שלום {{customer_name}},</p>
  <p>קיבלנו את התשלום שלך בסך {{amount}} ש"ח.</p>
  <p>מספר חשבונית: {{invoice_number}}</p>
</div>
```

**פורמט מטבע שקלי (ILS):**
ה-Formatter המובנה של Zapier לא תומך ב-ILS באופן מובנה. השתמש ב-Formatter by Zapier > Numbers > Format Number עם ההגדרות:
- שתי ספרות אחרי הנקודה
- מפריד עשרוני: `.` (נקודה)
- מפריד אלפים: `,` (פסיק)
- אז צרף " ש\"ח" או " ILS" בשלב שרשור טקסט

**פורמט תאריכים לישראל:**
מסמכים ישראליים משתמשים ב-DD/MM/YYYY. השתמש ב-Formatter by Zapier > Date/Time > Format עם:
- פורמט: `DD/MM/YYYY`
- אסור להשתמש בברירת המחדל MM/DD/YYYY, שתבלבל נמענים ישראליים

### שלב 4: בניית אוטומציות מחזור חיוב ישראלי

דיווח מס בישראל עוקב אחר מחזורים מוגדרים. בנה Zaps שמתואמים עם תקופות אלו.

**Zaps לתקופת מע"מ דו-חודשית:**
עסקים ישראליים מדווחים מע"מ דו-חודשית: ינואר-פברואר, מרץ-אפריל, מאי-יוני, יולי-אוגוסט, ספטמבר-אוקטובר, נובמבר-דצמבר. השתמש ב-Schedule by Zapier:
- טריגר: "Every Month" ביום ה-1
- הוסף שלב Filter: "המשך רק אם מספר החודש אי-זוגי" (ינואר=1, מרץ=3 וכו')
- זה מופעל ביום הראשון אחרי סגירת כל תקופה דו-חודשית
- פעולה: שלוף את כל החשבוניות/קבלות מהחודשיים הקודמים דרך API של חשבונית ירוקה והכן לדיווח מע"מ

**תזכורות מקדמות רבעוניות:**
עצמאים משלמים מקדמות מס רבעוניות. הגדר תזכורות:
- טריגר מתוזמן: חודשי ב-10 לחודש
- סינון: רק חודשים 1, 4, 7, 10 (ינואר, אפריל, יולי, אוקטובר)
- פעולה: שלח אימייל תזכורת עם מועד התשלום הקרוב וסכום משוער

**טריגרים לדוח שנתי:**
- תזמון: 15 בינואר
- פעולה: הכן סיכום שנתי מחשבונית ירוקה, שלח למייל רואה החשבון
- כולל: הכנסות כוללות, הוצאות כוללות, מע"מ ששולם, ניכוי מס במקור

**תאריכי מס מרכזיים לקידוד ב-Zaps:**

| תאריך | אירוע | פעולת Zap |
|--------|--------|----------|
| 15 לחודשים אי-זוגיים | מועד דיווח מע"מ | שליחת תזכורת 5 ימים לפני |
| 15 בינואר/אפריל/יולי/אוקטובר | מועד מקדמות | שליחת תזכורת + הערכת סכום |
| 15 בינואר | סיכום שנתי של השנה הקודמת | הכנה ושליחה לרואה חשבון |
| 31 במרץ | מועד הגשת דוח שנתי (לעצמאים עם רואה חשבון) | תזכורת הגשה |
| 30 באפריל | הגשת דוח שנתי (ללא הארכת רואה חשבון) | תזכורת הגשה |

### שלב 5: הגדרת חיבורים ישראליים מבוססי Webhook

מעבדי תשלומים ישראליים רבים ושירותים נוספים חסרים אינטגרציה מובנית ב-Zapier. השתמש ב-webhooks כגשר.

**Webhook תשלום קארדקום כטריגר Zap:**

קארדקום שולח בקשת POST עם פרטי תשלום בסיום עסקה. המטען כולל בדרך כלל:

| שדה | תיאור | דוגמה |
|-----|--------|-------|
| `Transaction` | מזהה עסקה | `12345678` |
| `Amount` | סכום תשלום באגורות (יש לחלק ב-100 לשקלים) | `15000` (= 150.00 ש"ח) |
| `CardNum` | 4 ספרות אחרונות | `1234` |
| `NumOfPayments` | מספר תשלומים | `3` |
| `CustomerName` | שם בעל הכרטיס | `ישראל ישראלי` |
| `Email` | אימייל לקוח | `israel@example.com` |
| `CustomFields` | נתונים מותאמים אישית | משתנה |

חשוב: קארדקום שולח סכומים באגורות. תמיד חלק ב-100 כדי לקבל שקלים. הוסף שלב Formatter > Numbers > Math > Divide by 100 מיד אחרי טריגר ה-webhook.

**Webhook תשלום טרנזילה:**

דומה לקארדקום אך עם שמות שדות שונים. שדות מרכזיים:

| שדה קארדקום | מקבילה בטרנזילה | הערות |
|-----------|---------------|-------|
| `Transaction` | `index` | מזהה עסקה |
| `Amount` | `sum` | כבר בשקלים (לא אגורות) |
| `CardNum` | `ccno` | 4 ספרות אחרונות |
| `NumOfPayments` | `npay` | תשלומים |

שים לב להבדל הקריטי: `sum` של טרנזילה בשקלים, `Amount` של קארדקום באגורות. טעות בזה היא מקור נפוץ לשגיאות חיוב.

### שלב 6: שימוש בתבניות Zap נפוצות לעסקים ישראליים

**תבנית 1: חשבונית-להנהלת-חשבונות (לעצמאים)**
1. טריגר: Green Invoice > מסמך חדש נוצר
2. סינון: סוג מסמך = "חשבונית מס" או "חשבונית מס קבלה"
3. פעולה: יצירת שורה ב-Google Sheets עם עמודות: תאריך, שם לקוח, סכום (לפני מע"מ), סכום מע"מ, סה"כ, מספר מסמך
4. פעולה: אם הסכום מעל 25,000 ש"ח, שלח התראה ב-Slack לערוץ רואה חשבון

**תבנית 2: הזמנה-לחשבונית (לחנות אונליין)**
1. טריגר: Shopify/WooCommerce > הזמנה חדשה
2. פעולה: יצירת מסמך בחשבונית ירוקה (סוג: קבלה או חשבונית מס קבלה לפי העדפת העסק)
3. פעולה: שליחת הודעת וואטסאפ דרך Twilio עם אישור הזמנה בעברית
4. פעולה: עדכון בורד Monday.com עם סטטוס הזמנה

**תבנית 3: תשלום-לקבלה**
1. טריגר: Webhooks by Zapier (catch hook של קארדקום)
2. פעולה: Formatter > Math > חלוקת סכום ב-100 (אגורות לשקלים)
3. פעולה: Green Invoice > יצירת מסמך (סוג: קבלה)
4. פעולה: שליחת מייל עם קישור ל-PDF הקבלה ללקוח
5. פעולה: רישום ב-Google Sheets להתאמה

**תבנית 4: לכידת ליד למעקב CRM בעברית**
1. טריגר: Typeform/Google Forms > תגובה חדשה
2. פעולה: Formatter > Text > Trim Whitespace (ניקוי קלט עברי)
3. פעולה: יצירת איש קשר ב-CRM (Monday.com או HubSpot)
4. פעולה: שליחת ברכה בוואטסאפ בעברית דרך Twilio
5. פעולה: תזמון משימת מעקב בעוד 3 ימים

**תבנית 5: קבלת הוצאה לסיווג**
1. טריגר: Gmail > מייל חדש עם קובץ מצורף התואם "קבלה" או "חשבון"
2. פעולה: Formatter > חילוץ סכום הקבלה מגוף המייל
3. סינון: המשך רק אם הסכום ניתן לניתוח
4. פעולה: סיווג לפי דומיין השולח (ספקים מוכרים) או מילות מפתח
5. פעולה: הוספה לגיליון "ניכויי מס" ב-Google Sheets עם עמודת קטגוריה

## דוגמאות

### דוגמה 1: קבלה אוטומטית לתשלומי קארדקום

המשתמש אומר: "אני רוצה ליצור קבלה אוטומטית בחשבונית ירוקה כשמישהו משלם דרך קארדקום"

פעולות:
1. יצירת Zap עם Webhooks by Zapier > Catch Hook כטריגר
2. הגדרת קארדקום לשלוח POST לכתובת ה-webhook על תשלום מוצלח
3. הוספת שלב Formatter: חלוקת `Amount` ב-100 (אגורות לשקלים)
4. הוספת פעולת Green Invoice > Create Document עם סוג "קבלה"
5. מיפוי שדות: שם לקוח, מייל, סכום, תיאור מתוך ה-webhook
6. הוספת פעולת מייל לשליחת קישור הקבלה ללקוח

תוצאה: כל תשלום קארדקום מוצלח מייצר אוטומטית קבלה בחשבונית ירוקה ושולח אותה ללקוח במייל.

### דוגמה 2: סיכום מע"מ דו-חודשי

המשתמש אומר: "שלח לי סיכום כל החשבוניות בסוף כל תקופת מע"מ לרואה החשבון שלי"

פעולות:
1. יצירת Zap עם Schedule by Zapier, הרצה ב-1 בכל חודש
2. הוספת סינון: המשך רק אם מספר החודש אי-זוגי (תחילת תקופת מע"מ חדשה)
3. הוספת פעולת Green Invoice > Find Documents עם סינון ל-2 החודשים הקודמים
4. הוספת Formatter לחישוב סה"כ הכנסות, סה"כ מע"מ שנגבה
5. הוספת פעולת מייל לרואה חשבון עם טבלת סיכום

תוצאה: ב-1 במרץ, מאי, יולי, ספטמבר, נובמבר וינואר, נשלח מייל אוטומטי לרואה החשבון עם סיכום חשבוניות התקופה הדו-חודשית.

### דוגמה 3: הודעת וואטסאפ בעברית על תשלום

המשתמש אומר: "שלח הודעת וואטסאפ בעברית ללקוחות כשהם משלמים"

פעולות:
1. הגדרת טריגר webhook לתשלום (קארדקום או טרנזילה)
2. הוספת Formatter להמרת סכום לשקלים ועיצוב עם " ש\"ח"
3. הוספת Formatter לבניית הודעה בעברית: "שלום {{name}}, קיבלנו תשלום בסך {{amount}} ש\"ח. תודה!"
4. הוספת פעולת Twilio > Send WhatsApp Message
5. הגדרת שדה "To" לטלפון הלקוח (ודא קידומת +972)

תוצאה: הלקוח מקבל אישור תשלום בוואטסאפ בעברית תוך שניות מהתשלום.

### דוגמה 4: אוטומציית סוף שנה לעצמאים

המשתמש אומר: "אני צריך Zap שמכין סיכום שנתי של החשבוניות שלי להגשת מס"

פעולות:
1. יצירת Zap עם Schedule by Zapier, הרצה ב-15 בינואר
2. הוספת פעולת Green Invoice > Find Documents לכל השנה הקודמת
3. הוספת שלב Code by Zapier לחישוב סיכומים: הכנסות, הוצאות, מע"מ, ניכוי מס במקור
4. הוספת פעולת Gmail לשליחת סיכום מעוצב לרואה החשבון
5. הוספת פעולת Google Sheets לארכיון הסיכום השנתי

תוצאה: נתוני הכנת מס שנתיים נאספים אוטומטית ונשלחים לרואה החשבון בכל ינואר.

## מלכודות נפוצות

- **בלבול אגורות מול שקלים**: קארדקום שולח סכומים באגורות (1/100 שקל), אבל טרנזילה שולחת בשקלים. סוכנים לרוב מניחים שכל סכומי התשלום באותה יחידה. תמיד בדוק באיזה מעבד מדובר והוסף שלב חלוקה ב-100 לקארדקום.
- **אי-התאמת פורמט תאריך**: Zapier מגדיר כברירת מחדל פורמט תאריך אמריקאי (MM/DD/YYYY). מסמכים, חשבוניות וטפסי מס ישראליים משתמשים ב-DD/MM/YYYY. תמיד הוסף שלב עיצוב תאריך מפורש. אי-ביצוע זה עלול לגרום לתאריך חשבונית כמו "03/01/2026" להתפרש כ-3 בינואר במקום 1 במרץ.
- **עברית בשלבי קוד**: בשימוש ב-"Code by Zapier" (JavaScript או Python), מחרוזות עברית בגוף הקוד עובדות, אבל עברית בשמות משתנים תשבור את הקוד. שמור שמות משתנים באנגלית, השתמש בעברית רק בערכי מחרוזות.
- **סוגי מסמכים בחשבונית ירוקה**: סוכנים לרוב בוחרים כברירת מחדל "חשבונית מס" כשהמשתמש צריך "חשבונית מס קבלה" או "קבלה". שאל את המשתמש איזה סוג מסמך הוא צריך. בישראל, קבלה מונפקת אחרי תשלום, חשבונית מס לפני או בזמן מכירה, וחשבונית מס קבלה משלבת את שניהם.
- **פורמט מספר טלפון לוואטסאפ**: מספרי נייד ישראליים חייבים לכלול קידומת +972 ולהשמיט את ה-0 המוביל (למשל 0541234567 הופך ל-+972541234567). סוכנים נוטים להעביר את הפורמט המקומי, מה שגורם לשליחות Twilio WhatsApp להיכשל בשקט.
- **שיעור מע"מ**: שיעור המע"מ הנוכחי בישראל הוא 18% (נכון לינואר 2025). סוכנים לפעמים משתמשים בשיעור המיושן של 17% בחישובים. תמיד אמת את השיעור העדכני לפני בניית שלבי Zap הקשורים למס.
- **חיפוש עברי ב-Zapier**: בחיפוש אפליקציות ישראליות בספריית האפליקציות של Zapier, חפש באנגלית ("Green Invoice", לא "חשבונית ירוקה"). שמות האפליקציות ב-Zapier הם באנגלית גם לאפליקציות ממקור ישראלי.
- **מגבלות החינמי**: המסלול החינמי של Zapier תומך רק ב-Zaps חד-שלביים (טריגר אחד, פעולה אחת). רוב האוטומציות העסקיות הישראליות דורשות Zaps רב-שלביים. ודא שהמשתמש יודע שהוא צריך מסלול בתשלום לתהליכי עבודה אמיתיים.

## פתרון בעיות

### שגיאה: "Webhook לא מקבל נתונים מקארדקום"
סיבה: כתובת webhook של קארדקום מוגדרת בצורה שגויה או המסוף במצב בדיקה
פתרון: ודא את כתובת ה-webhook בהגדרות מסוף קארדקום תחת "התראות". ודא שהמסוף במצב ייצור ולא sandbox. בצע תשלום אמיתי בסכום קטן (1 ש"ח) לבדיקה. בדוק בהיסטוריית webhook של Zapier אם יש בקשות נכנסות.

### שגיאה: "חשבונית ירוקה מחזירה 401 Unauthorized"
סיבה: מפתח API לא תקין או שפג תוקפו
פתרון: צור מפתח API חדש מדשבורד חשבונית ירוקה (הגדרות > אינטגרציית API). אמת מחדש את חיבור חשבונית ירוקה ב-Zapier. מפתחות API לא פגים אוטומטית, כך שזה בדרך כלל אומר שהמפתח נוצר מחדש או שתוכנית החשבון השתנתה.

### שגיאה: "טקסט עברי מופיע משובש באימיילים"
סיבה: תבנית אימייל חסרה charset UTF-8 או כיוון RTL
פתרון: עטוף תוכן עברי בתגית `<div dir="rtl">`. ודא שה-HTML של האימייל כולל `<meta charset="UTF-8">` ב-head. אם משתמשים באימייל טקסט רגיל, עברית אמורה להופיע נכון בלקוחות מודרניים אך עלולה להופיע הפוכה בישנים יותר.

### שגיאה: "הסכום גדול פי 100 מהמצופה בחשבונית ירוקה"
סיבה: סכום webhook של קארדקום הוא באגורות ולא בשקלים
פתרון: הוסף שלב Formatter > Numbers > Math > Divide by 100 בין טריגר ה-webhook לפעולת חשבונית ירוקה. זו השגיאה הנפוצה ביותר ב-Zaps של קארדקום-לחשבונית-ירוקה.
