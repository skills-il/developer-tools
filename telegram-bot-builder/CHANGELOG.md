# Changelog

## 1.4.0 - 2026-08-27

Bot API version cycle, plus three defects the version bump surfaced.

- **Bot API 10.2 -> 10.3** (released 24 August 2026) across both languages, `metadata.json` and every reference file. A new "What Bot API 10.3 Changed" section names the four things that moved for anyone who learned this surface on 10.2.
- **The ephemeral-message shape from 10.2 is dead.** 10.3 replaced `receiver_user_id` and `callback_query_id` on `sendMessage` and twelve sibling methods with a single `ephemeral_message_parameters` object. Any sample dated before 24 August 2026, including anything a model learned, uses the superseded shape. Added as a Gotcha as well as a section.
- **grammY 1.45.1 -> 1.46.0** (2026-08-26, "feat: support Bot API 10.3"). It is now the only one of the three frameworks on 10.3. Telegraf 4.16.3 (2024-02-29, Bot API 7.1) and python-telegram-bot 22.8 (Bot API 10.0) were re-confirmed against the npm registry and PyPI and are unchanged.
- **Fabricated API surface removed.** The skill told readers to use "the `paid_media` field on `sendMessage`-style methods". No such parameter exists: in the live reference `paid_media` appears only as an incoming field on `Message`, inside `PaidMediaInfo`, and on `StarTransaction`. `sendPaidMedia` is the only way to send paid media. Both languages.
- **The paid-broadcast eligibility gate was missing.** This cycle first added paid broadcasts (1000 msg/sec at 0.1 Stars above the free 30/sec) as a scaling path, then found the FAQ's next sentence: a bot needs "at least 100,000 Stars on its balance and at least 100,000 monthly active users". Almost no Israeli SMB bot clears that, so the section now leads with the gate and gives the FAQ's actual advice for everyone below it, spreading the broadcast over 8-12 hours.
- **Stars subscriptions were driven off the wrong update.** The skill said to listen for `message:successful_payment` on each renewal. That handler sees a renewal charge and never sees a cancellation. Bot API 10.2 added `BotSubscriptionUpdated` and the `subscription` field on `Update` for exactly this, and the skill now points at it.
- **Business-account setters corrected.** `references/domain-checklist.md` implied a `remove*` variant for each of Name, Username, Bio, ProfilePhoto and GiftSettings. Only `removeBusinessAccountProfilePhoto` exists; the rest are set-only.
- **`MainButton.text =` replaced with `setText()`** in the Mini App checkout example. Direct property assignment never reaches the client, so the only worked Mini App flow shipped a confirm button rendering Telegram's default "Continue" label.
- Added the **4096-byte `sendData` cap**, which a serialised cart crosses silently on a real order; the `subscription_period` claim was softened from "exists ONLY on `createInvoiceLink`" (it is also required on `createChatSubscriptionInviteLink`); the Telegram Business non-Premium quote is now attributed to `core.telegram.org/api/business`, where it actually appears, with a note that the changelog words the same 10.0 item as "Business Bots" rather than "Secretary Bots"; and the `file_id` quote is now verbatim.
- **Eight Hebrew strings had a bidi authoring artefact**, a sentence-final `!` sitting at the start of the string literal (`"!שלום! אני הבוט שלך"`). Fixed across `SKILL_HE.md` and four reference files. Poor look in the one skill whose selling point is Hebrew and RTL correctness.
- Structural: several code blocks moved from both bodies into `references/examples.md` and `references/mini-apps.md`, which brought both languages under the 5,000-word cap and closed a divergence where the Hebrew file still carried inline what the English file had already moved out.

**Verification note for the next cycle.** `core.telegram.org` returns **HTTP 200 with a full-looking page for fabricated paths**, so a status code proves nothing there. Every check in this cycle asserted on page content: for "does this identifier exist", the test is its presence in the reference's anchor set, not a 404.
